# `0.2.0` 译制工作间计划

本文是 `0.2.0` 的短期产品与架构执行契约，只描述下一阶段目标、顺序和不变量，不把规划中的能力写成当前事实。当前公开能力仍以仓库根 [`README.md`](../README.md) 和 [`FRONTEND_PRODUCT_SURFACES.md`](FRONTEND/current/FRONTEND_PRODUCT_SURFACES.md) 为准；实施完成后，稳定结论回写对应专题文档，本计划再归档。

## 产品承诺

TransVortex 从“能够完成一次字幕任务的工具”发展为“能按用户意愿积累翻译知识、支持专业审校与成品交付，并具有强烈视觉人格的个人译制工作间”。

核心循环是：

```text
独立持久术语库（可人工维护，也可由 Agent 操作）
  -> 按任务选择并冻结术语快照
  -> 字幕制作与任务内动态候选
  -> 质量审校与编辑
  -> 成品样式与预览
  -> 导出交付
  -> 用户选择哪些候选值得持久化
  -> 后续任务更准确、更一致
```

## 产品表面

下一阶段围绕四个一级产品概念组织能力：

1. **术语库**：独立维护可复用的人物、地点、称谓、固定表达和 ASR 修正；不要求先创建作品，也不绑死某个任务。
2. **任务记忆**：任务运行中可动态生成候选用于增强当次翻译，但只有用户明确选择后才进入持久术语库。
3. **字幕工作台**：同步媒体与字幕，完成文本、时间码、质量问题和一致性审校。
4. **交付工作室**：管理内容布局、成品样式、预览、格式和重新导出。

作品 / 系列仍可在未来作为任务组织和术语库默认选择来源，但不是持久记忆的所有者，也不是术语连续性的前置条件。

Provider、ASR、网络、Agent 和资源管理仍是支持这些目标的设置能力，不作为产品叙事中心。面向用户使用“自动发现候选”“使用术语库”“保存所选候选”“锁定译法”等概念，不直接公开 `bootstrap`、`inject`、`patch`、checkpoint、retry schema 或 ASR manifest 等实现字段。

## 阶段顺序

### M0：产品表面定稿与简单架构治理（已完成）

M0 已于 2026-08-07 完成。稳定所有权已经回写当前架构与前端专题文档；具体行为护栏、热点基线、执行批次和验证记录见 [`archive/2026-08-07-architecture-governance-m0.md`](archive/2026-08-07-architecture-governance-m0.md)。

- 冻结了作品、术语、编辑和交付之间的入口、状态与所有权，没有把规划中的产品概念伪装成当前能力。
- 拆分了 Flutter 主窗口、设置窗、App Service client、任务处理、结果审看和高频测试职责。
- 保留 Python orchestrator 的稳定 pipeline 入口，提取 ASR planning / execution、阶段 controller 及 source / translation / delivery helper。
- Flutter / Python 职责、RPC、任务工件、配置和凭据语义保持不变；定向回归与静态检查通过。

M0 没有追求统一行数、消除全部既有依赖环或拆完所有大文件。后续只在具体 M1 改动触及边界时继续治理。

### M1：`0.2.0` 工作台闭环

- 完成独立术语库、任务选择、冻结快照、人工维护和任务候选选择性持久化的基础闭环。
- 继续补充候选证据、批量合并 / 导入导出和更细的冲突审看；作品 / 系列组织能力不阻塞该闭环。
- 完成媒体定位、字幕文本与时间码编辑、撤销 / 重做、查找替换和问题导航所需的编辑闭环；不以复制专业 NLE 全部能力为目标。
- 建立字幕交付样式系统，区分内容布局与 ASS 等格式承载的视觉样式，并支持预览、任务快照和重新导出。
- 随产品表面实现第一批导入、运行、失败恢复和完成交付场景，不把视觉深化推迟到所有功能之后。

### M2：质量复利与极致视觉

- 从人工修改中提出可预览、可拒绝的术语库更新。
- 检查跨任务名称、称谓、固定表达和常见 ASR 错误的一致性。
- AI 审校只生成受控 patch，不直接整片覆盖用户结果。
- 深化 Shader、粒子、角色、音效和 2D / 2.5D CG；演出使用真实任务状态，并保留减少动态效果版本和 Windows Release 性能底线。

### M3：Android 伴侣端预研

优先验证移动端查看任务进度、接收完成通知、审看字幕、确认术语和进行轻量修改的伴侣场景。Python core、FFmpeg、ASR 和任务工件先继续由 Windows 主机持有。

完整独立 Android 客户端需要另行决定 Python / FFmpeg runtime、后台执行、文件权限、本机 ASR、凭据存储和移动布局，不属于当前承诺。

## 稳定边界与非目标

- Flutter 继续是唯一产品前端，不新增第二套桌面前端。
- Python core、任务协议和结构化 segments 继续是字幕业务真实来源。
- 不为架构治理修改已发布协议语义，也不借拆分引入新的状态管理框架。
- `0.1.x` 只处理阻塞缺陷、安全问题和确有必要的发布修正；主开发面向 `0.2.0`。
- 完整发布 CI、App Host / Supervisor、ASR 资源跨盘迁移、更多 provider、多 Worker、macOS / Linux 和完整独立 Android runtime 不自动进入当前主线。

## `0.2.0` 旗舰验收场景

1. 用户创建或选择一个独立术语库，并在至少两个任务中选择使用；不要求创建作品实体。
2. 系统从第一份内容生成任务候选；未选择的候选只增强当次翻译，不自动成为长期资产。
3. 所选术语库按 revision 冻结为任务快照并参与字幕制作，后续编辑术语库不会暗改旧任务。
4. 用户从结果中只勾选适合复用的候选，预览冲突后提升到持久术语库。
5. 用户预览并选择成品样式，导出后仍可更换交付设置重新导出。
6. 后续任务复用项目记忆，同时保持用户可见、可审看和可撤销的控制边界。

视觉验收与上述流程一起进行：关键状态应具有明确品牌记忆点，但不得伪造进度、成功、失败、保存或交付结果。
