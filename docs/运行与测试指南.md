# TransVortex 运行与测试指南

本文集中维护开发、构建和验收入口。公开发布状态以 [`CURRENT_BACKLOG.md`](CURRENT_BACKLOG.md) 为准。

## 1. Python 开发环境

```powershell
python -m pip install -e .[test]
transvortex doctor --json
python -m pytest -q
```

开发态需要进程内本机 ASR 时：

```powershell
python -m pip install -e .[asr]
```

显式仓库 CLI 使用系统 `ffmpeg` / `ffprobe`。正式安装包使用包内固定 runtime。

## 2. 凭据和连接检查

默认把 key 保存到用户级 `~/.transvortex/auth.json`：

```powershell
transvortex auth set <credential-id>
transvortex auth status --json
transvortex probe-provider --strict
```

`providers.local.yaml` 可保存本机 provider 配置，但不能保存 key。环境变量和项目 `.env` 只作为开发兼容方式，不是桌面端默认凭据方案。

## 3. CLI 最小验证

无视频或无 ASR 环境时，先用 source segments 验证翻译和导出：

```powershell
transvortex translate `
  --segments .\samples\asr_segments_sample.jsonl `
  --src en --tgt zh-CN --bilingual --output-format both --json
```

真实媒体任务：

```powershell
transvortex run `
  --input "DemoTest/英文视频.mp4" `
  --src en --tgt zh-CN --bilingual --output-format both --json
```

Agent 或脚本使用分离模式：

```powershell
transvortex run --input demo.mp4 --src en --tgt zh-CN --detach --json
transvortex events --task-id <task_id> --follow
transvortex status --task-id <task_id> --json
```

## 4. 外部服务 smoke

验证真实翻译 provider：

```powershell
.\scripts\smoke_external_services.ps1 -ProvidersFile .\providers.local.yaml
```

同时验证媒体、ASR 和导出：

```powershell
.\scripts\smoke_external_services.ps1 `
  -ProvidersFile .\providers.local.yaml `
  -InputPath "DemoTest/英文视频.mp4" `
  -RequireMediaTask
```

`-PlanOnly` 只打印计划，不访问外部服务，也不构成通过证据。

## 5. Flutter 开发验证

```powershell
Set-Location desktop_flutter
flutter analyze
flutter test
flutter build windows
```

当前用户可见窗口是主窗口、翻译模型设置、语音识别设置和任务处理；诊断窗口只供开发、测试和支持使用。

从仓库根运行 release smoke：

```powershell
.\scripts\smoke_flutter_release.ps1 -ScreenshotPath "$env:TEMP\transvortex-main.png"
.\scripts\smoke_flutter_release.ps1 -CheckNotifications -CheckAppIdentity
.\scripts\smoke_flutter_release_matrix.ps1 -CheckDesktopComposite
```

矩阵覆盖主窗口状态、设置窗、诊断、任务处理和通知接线。自动截图与 smoke 不替代完整人工操作。

## 6. Runtime 与安装器

构建固定主 Python 和 FFmpeg runtime：

```powershell
.\scripts\build_app_runtime.ps1 -Force -Json
.\scripts\build_ffmpeg_runtime.ps1 -Force -Json
```

生成 portable release：

```powershell
.\scripts\package_flutter_release.ps1 `
  -OutputRoot "$env:TEMP\transvortex-release" `
  -PackageName TransVortex-portable-test `
  -Force -LaunchCheck
```

生成并验收 NSIS 内部安装包：

```powershell
.\scripts\build_windows_installer.ps1 -AllowUnsigned -Force
.\scripts\accept_windows_installer.ps1
```

`-AllowUnsigned` 只允许内部验收件。安装器自动验收覆盖目录保护、全新安装、固定 runtime、升级、运行中保护、AUMID 快捷方式、卸载和用户数据保留。

## 7. 人工桌面验收

启动检查：

```powershell
.\scripts\accept_flutter_release_manual.ps1 -LaunchCheck
```

完整真实窗口任务：

```powershell
.\scripts\accept_flutter_release_manual.ps1 -InputPath "DemoTest/英文视频.mp4"
```

人工确认范围：选择片源、提交、观察运行、完成或取消、打开结果、进入任务处理并审看结果。

最终 Release Candidate 还必须在正式安装目录和干净 Windows 环境重跑精简真实任务，并验证通知归属和点击聚焦。

## 8. 验证选择

- Python 小改：相关 pytest。
- Python 核心流程或跨模块改动：优先全量 `pytest -q`。
- Flutter UI 或 worker protocol：`flutter analyze` + `flutter test`。
- 主流程或发布布局：补 `flutter build windows` 和对应 release smoke。
- 安装器或 runtime：构建与安装器验收脚本。
- 凭据、provider、ASR 和翻译：对应最小测试，并在外部条件具备时跑真实服务 smoke。

无法执行的验证必须说明原因和剩余风险。
