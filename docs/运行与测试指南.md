# TransVortex 运行与测试指南（简化版）

目标只有一个：最快确认项目可用。

## 1. 三步跑通

在项目根目录执行：

```powershell
.\.venv\Scripts\Activate.ps1
$env:TVX_MODEL_API_KEY = "你的key"
transvortex doctor --providers-file .\providers.local.yaml
transvortex probe-provider --providers-file .\providers.local.yaml --strict
python -m pytest -q
```

如果看到测试全部通过，说明基础功能正常。

## 2. 无视频/无 ASR 的真实翻译验证

低配机器或暂时没有视频样例时，可以直接用一份 ASR 聚合产物样本验证真实 provider 的翻译、质量处理和导出链路。这个路径不需要 FFmpeg 或 `faster-whisper`，但需要真实 provider key。

样本格式对齐归一化 source artifact `source/segments.normalized.jsonl`：每行一个 segment，包含 `id`、`start`、`end`、`text_src`、`confidence`。

```powershell
$env:TVX_MODEL_API_KEY = "你的key"
transvortex probe-provider --providers-file .\providers.local.yaml --strict
transvortex translate --providers-file .\providers.local.yaml --segments .\samples\asr_segments_sample.jsonl --src en --tgt zh-CN --bilingual --output-format both --json
```

如果暂时没有 `providers.local.yaml`，也可以用当前默认的 `providers.yaml`：

```powershell
transvortex translate --segments .\samples\asr_segments_sample.jsonl --src en --tgt zh-CN --bilingual --output-format both --json
```

输出会写入 `artifacts/<task_id>/output/`，包含真实模型生成的 SRT/ASS。这个验收绕过 ASR，因此适合先验证 provider、prompt、翻译校验、质量处理和导出。

也可以用固定 smoke 脚本产出机器可读证据：

```powershell
.\scripts\smoke_external_services.ps1 -ProvidersFile .\providers.local.yaml
```

如果要同时覆盖真实媒体输入和 ASR/导出链路，传入 `-InputPath`：

```powershell
.\scripts\smoke_external_services.ps1 -ProvidersFile .\providers.local.yaml -InputPath "DemoTest/英文视频.mp4" -RequireMediaTask
```

没有 key 或本机媒体样例时，可以先用 `-PlanOnly` 查看将要执行的验收步骤；这个模式不会访问外部服务，也不代表前端设计 MVP 已完成。

## 3. 更省事的两种方式

1) 用 `.env`（推荐）

在项目根目录创建 `.env`：

```dotenv
TVX_MODEL_API_KEY=你的key
```

程序会自动读取 `.env`，且不会覆盖你已经在终端里设置的环境变量。

2) 用一键脚本

```powershell
.\scripts\run_demo.ps1 -ApiKey "你的key" -InputPath "DemoTest/英文视频.mp4"
```

脚本会自动执行：
- `doctor`
- `probe-provider --strict`
- `run`
- `status`

## 4. V1 验收路径

```powershell
.\.venv\Scripts\Activate.ps1
$env:TVX_MODEL_API_KEY = "你的key"
transvortex doctor --providers-file .\providers.local.yaml --json
transvortex probe-provider --providers-file .\providers.local.yaml --strict
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual --json
```

验收重点：
- `doctor --json` 总体不应为 `FAIL`
- `probe-provider --strict` 退出码为 0
- 任务状态为 `DONE`
- `artifacts/<task_id>/events.jsonl` 存在
- `artifacts/<task_id>/checkpoint.json` 不残留旧 error
- `artifacts/<task_id>/output/*.srt` 存在

如需同时验收 ASS：

```powershell
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual --output-format both --json
```

额外检查：
- `task.json` 包含 `output_paths.srt` 和 `output_paths.ass`
- `output/*.ass` 存在，并可被播放器或字幕工具识别

## 5. 跑端到端

```powershell
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual
```

输出在 `artifacts/<task_id>/output/*.srt`。

## 6. Worker/Agent 常用命令

```powershell
transvortex doctor --providers-file .\providers.local.yaml --json
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual --json
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual --detach --json
transvortex run --providers-file .\providers.local.yaml --input "DemoTest/英文视频.mp4" --src en --tgt zh-CN --bilingual --stream-events
transvortex status --task-id <task_id> --json
transvortex events --task-id <task_id>
transvortex cancel --task-id <task_id> --json
transvortex tasks --json
transvortex config show --json
```

说明：`run --json` 是前台长任务，只有任务结束后才输出最终 JSON。Agent 或脚本需要立即拿到 `task_id` 时，应使用 `run --detach --json`，这个返回只是排队回执，不是最终结果；应继续用 `status` 和 `events --follow` 跟踪。

每个任务目录固定包含：
- `task.json`
- `checkpoint.json`
- `events.jsonl`
- `media/`
- `asr/`
- `chunks/`
- `translate/`
- `final/`
- `output/`

## 7. 桌面工作台

主体验桌面端在 `desktop_flutter/`。`desktop/` Tauri 版本已经冻结为参考实现，不再作为日常验收路径。

Flutter 桌面端定位是 V1 日常主入口：拖拽/选择视频、配置翻译服务和语音识别、启动/停止任务，查看诊断、历史任务、任务详情和结果审看。

前置条件：
- Flutter Windows desktop 环境
- Python 依赖已安装：`python -m pip install -e .[test]`
- 真实 ASR 时安装：`python -m pip install -e .[asr]`
- `ffmpeg` / `ffprobe` 已加入 `PATH`

前端检查：

```powershell
cd desktop_flutter
flutter test
flutter analyze
flutter build windows
```

Windows release 产物位于 `desktop_flutter\build\windows\x64\runner\Release\TransVortex.exe`。

启动 Flutter 桌面端：

```powershell
cd desktop_flutter
flutter run -d windows
```

release smoke：

```powershell
.\scripts\smoke_flutter_release.ps1 -ScreenshotPath "$env:TEMP\transvortex-main.png"
.\scripts\smoke_flutter_release.ps1 -CheckNotifications -CheckAppIdentity
.\scripts\smoke_flutter_release_matrix.ps1 -SkipCompletedTask
.\scripts\smoke_flutter_release.ps1 -MainPhase empty -CheckDesktopComposite
.\scripts\build_app_runtime.ps1 -Force
.\scripts\package_flutter_release.ps1 -OutputRoot "$env:TEMP\transvortex-release" -PackageName TransVortex-portable-test -Force -LaunchCheck
.\scripts\install_flutter_portable_release.ps1 -SourceRoot "$env:TEMP\transvortex-release\TransVortex-portable-test" -InstallRoot "$env:TEMP\transvortex-installed" -ShortcutPath "$env:TEMP\TransVortex.lnk" -Force
.\scripts\accept_flutter_release_manual.ps1 -LaunchCheck
.\scripts\accept_flutter_release_manual.ps1 -InputPath "DemoTest/英文视频.mp4"
```

`scripts\build_app_runtime.ps1` 先构建固定的 Windows Embedded Python 主 runtime，安装 TransVortex wheel 和锁定的主依赖。`scripts\package_flutter_release.ps1` 生成 portable release 包：它把 Flutter release 文件、主 runtime、`prompts/`、`pipeline.yaml`、由 `providers.example.yaml` 复制出的 `providers.yaml`、用户级安装脚本和开始菜单快捷方式辅助脚本放在同一包内，并排除 `.env`、`providers.local.yaml`、`auth.json` 等本地凭据文件。脚本直接从包根启动 `runtime\python\python.exe -m transvortex.app_service --no-pump`，在空 `PYTHONPATH` 下验证 `service.info` / `service.health` / `asr.status` / `service.shutdown`，并核对 runtime 清单版本；`-LaunchCheck` 额外验证包目录里的 `TransVortex.exe` 能启动真实窗口。包根的 `Install-TransVortex.ps1` 或仓库里的 `scripts\install_flutter_portable_release.ps1` 可把 portable 包复制到用户级安装目录、创建 AUMID 快捷方式，并在安装目录复跑同样的 Local Service RPC 检查。该路径内置主 Python runtime，但不内置 FFmpeg、本机 Whisper runtime、模型或 CUDA，也不是 MSIX/MSI/NSIS/Inno 安装器。详细边界见 `docs/APP_RUNTIME.md`。

桌面端 V1 验收：
- 主窗口能读取本地服务状态、翻译服务和语音识别默认配置。
- 翻译模型设置、语音识别设置、诊断、任务历史、任务详情和结果审看窗口能从主菜单或任务入口打开。
- 运行任务后能停止、继续、打开任务目录、打开结果目录，并能重新导出结果。
- `task.json` 固化本次翻译 / 语音识别配置和 `output_paths`。
- 自动 smoke 的 `frontend_design_mvp_complete=false` 是刻意保留的边界；真实外部翻译 / 语音识别可用 `scripts\smoke_external_services.ps1` 在当前用户凭据下单独验收；系统通知横幅已由人工确认出现，Windows 通知设置 key 已由 release smoke 校验；AppUserModelID 开始菜单快捷方式可用 `scripts\install_flutter_desktop_shortcut.ps1` 或 release smoke 的 `-CheckAppIdentity` 创建并校验。portable 包现在可用脚本生成，并会做包内 Local Service RPC 检查、用户级脚本安装检查和可选窗口启动检查，但它仍不是正式安装器。真实可见窗口完整人工操作用 `scripts\accept_flutter_release_manual.ps1` 记录逐步确认、窗口截图和 JSON 报告；正式跑人工前可用 `-LaunchCheck` 只验证 release 窗口启动和截图链路。正式 MSIX / installer 分发包仍是后续打包工作。

## 8. 常见问题

- 默认 prompt 在哪里改？
  - 默认文件在 `prompts/translation/` 和 `prompts/memory/`，代码内还有极简兜底文本。
  - `pipeline.yaml` 的 `prompts.translation_system`、`prompts.translation_style`、`prompts.memory_patch_system` 可以指向自定义文件。
  - `translation.style_prompt` 仍可直接覆盖字幕风格 prompt；留空字符串表示不追加风格提示。

- `No module named pytest`
  - 执行：`python -m pip install -e .[test]`
- `faster-whisper is required for ASR`
  - 执行：`python -m pip install -e .[asr]`
- `Missing environment variable: TVX_MODEL_API_KEY`
  - 检查是否设置了终端环境变量，或在项目根目录创建了 `.env`
- CUDA 相关报错（例如 `cublas64_12.dll`）
  - 先把 `pipeline.yaml` 的 `asr.device` 设为 `cpu`
