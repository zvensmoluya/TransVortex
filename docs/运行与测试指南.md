# TransVortex 运行与测试指南

本文集中维护开发、构建和验收入口。公开发布状态以 [`CURRENT_BACKLOG.md`](CURRENT_BACKLOG.md) 为准。

## 1. Python 开发环境

```powershell
python -m pip install -e .[test]
transvortex doctor --json
python -m pytest -q
```

开发态需要进程内本机 ASR 时：

```powershell
python -m pip install -e .[asr]
```

显式仓库 CLI 使用系统 `ffmpeg` / `ffprobe`。正式安装包使用包内固定 runtime。

## 2. 凭据和连接检查

默认把 key 保存到用户级 `~/.transvortex/auth.json`：

```powershell
transvortex auth set <credential-id>
transvortex auth status --json
transvortex probe-provider --strict
```

`providers.local.yaml` 可保存本机 provider 配置，但不能保存 key。环境变量和项目 `.env` 只作为开发兼容方式，不是桌面端默认凭据方案。

## 3. CLI 最小验证

无视频或无 ASR 环境时，先用 source segments 验证翻译和导出：

```powershell
transvortex translate `
  --segments .\samples\asr_segments_sample.jsonl `
  --src en --tgt zh-CN --bilingual --output-format both --json
```

真实媒体任务：

```powershell
transvortex run `
  --input "DemoTest/英文视频.mp4" `
  --src en --tgt zh-CN --bilingual --output-format both --json
```

Agent 或脚本使用分离模式：

```powershell
transvortex run --input demo.mp4 --src en --tgt zh-CN --detach --json
transvortex events --task-id <task_id> --follow
transvortex status --task-id <task_id> --json
```

## 4. 外部服务 smoke

验证真实翻译 provider：

```powershell
.\scripts\smoke_external_services.ps1 -ProvidersFile .\providers.local.yaml
```

同时验证媒体、ASR 和导出：

```powershell
.\scripts\smoke_external_services.ps1 `
  -ProvidersFile .\providers.local.yaml `
  -InputPath "DemoTest/英文视频.mp4" `
  -RequireMediaTask
```

`-PlanOnly` 只打印计划，不访问外部服务，也不构成通过证据。

## 5. Flutter 开发验证

```powershell
Set-Location desktop_flutter
flutter analyze
flutter test
flutter build windows
```

当前用户可见窗口是主窗口、翻译模型设置、语音识别设置和任务处理；诊断窗口只供开发、测试和支持使用。

从仓库根运行 release smoke：

```powershell
.\scripts\smoke_flutter_release.ps1 -ScreenshotPath "$env:TEMP\transvortex-main.png"
.\scripts\smoke_flutter_release.ps1 -CheckNotifications -CheckAppIdentity
.\scripts\smoke_flutter_release_matrix.ps1 -CheckDesktopComposite
```

矩阵覆盖主窗口状态、设置窗、诊断、任务处理和通知接线；任务处理编辑场景会保存译文与时间码，并验证 ASS 的实际时间、双语顺序和换行方案。自动截图与 smoke 不替代完整人工操作。

### 使用工作区 ASR 环境运行 APP E2E

开发阶段不需要先打包安装。下面的脚本会创建隔离的 APP 数据目录，探测本机 Python、CUDA 和 faster-whisper 模型，完成最小转录后登记为 `external` runtime，再启动可见的 Flutter Release APP。实际本机 Whisper 任务仍通过 `local_worker` 启动独立 JSONL 子进程，不会退回旧的进程内 ASR：

```powershell
.\scripts\run_flutter_app_e2e.ps1 `
  -InputPath "DemoTest/英文视频.mp4" `
  -Device cuda
```

需要固定本机环境时，可显式传入 `-PythonExecutable`、`-ModelPath` 和 `-ProvidersFile`。脚本会用清单中 `config.json` 的 SHA-256 验证 `ModelPath` 与 `ModelId` 一致。只检查计划、准备环境或启动窗口时分别使用：

```powershell
.\scripts\run_flutter_app_e2e.ps1 -PlanOnly -SkipBuild -Json
.\scripts\run_flutter_app_e2e.ps1 -PrepareOnly -Device cuda -Json
.\scripts\run_flutter_app_e2e.ps1 -LaunchCheck
```

运行完整验收前，需要从窗口或托盘明确退出已有 TransVortex。脚本通过临时 `LOCALAPPDATA` 隔离配置、任务和缓存，同时清除继承的 `TRANSVORTEX_HOME`；用户级凭据仍从 `~/.transvortex/auth.json` 读取，不会复制凭据，也不会修改正常桌面 APP 的用户数据。

`-PlanOnly`、`-PrepareOnly` 和 `-LaunchCheck` 都不构成 APP 端到端通过证据。完整验收必须使用确实需要 ASR 的无内嵌字幕视频或音频，在可见窗口中提交并完成翻译任务、打开并审看结果。脚本随后校验任务、Worker、全部 ASR 分段、输出文件，以及 ASR 行中的 `faster_whisper + runtime_source=external` 证据，并在会话根目录生成 `app_e2e_session.json`。带内嵌字幕而绕过 ASR 的任务会被判定为未通过。

验收期间不要在语音识别设置中保存本机 Whisper 配置；产品编辑器会按设计恢复受管 runtime 策略并覆盖开发桥接配置。该桥接只验证工作区构建、Flutter、Local Service 和独立 Worker 链路，不覆盖受管组件下载、正式安装目录或干净 Windows 验收。

阶段验证结论：2026-07-17 已使用真实媒体完成第一阶段可见 APP E2E，覆盖 external `local_worker` 识别、翻译、运行态观察、结果审看、字幕编辑和重新导出。机器证据与体验结论见 [`archive/e2e-reports/2026-07-17-flutter-app-e2e-first-stage.md`](archive/e2e-reports/2026-07-17-flutter-app-e2e-first-stage.md)。

## 6. Runtime 与安装器

构建固定主 Python 和 FFmpeg runtime：

```powershell
.\scripts\build_app_runtime.ps1 -Force -Json
.\scripts\build_ffmpeg_runtime.ps1 -Force -Json
```

生成 portable release：

```powershell
.\scripts\package_flutter_release.ps1 `
  -OutputRoot "$env:TEMP\transvortex-release" `
  -PackageName TransVortex-portable-test `
  -Force -LaunchCheck
```

生成并验收 NSIS 内部安装包：

```powershell
.\scripts\build_windows_installer.ps1 -AllowUnsigned -Force
.\scripts\accept_windows_installer.ps1
```

`-AllowUnsigned` 只允许内部验收件。安装器自动验收覆盖目录保护、全新安装、固定 runtime、升级、运行中保护、AUMID 快捷方式、静默卸载默认保留用户数据，以及安装包内 runtime 对自选 ASR 资源、设置、任务和凭据的分项清理。安装器品牌位图由 `scripts\build_brand_assets.ps1` 生成；改动 SVG 或应用图标后应先重建品牌资产。

交互卸载会显示四类清理选项。静默卸载默认不删除用户数据；自动化需要显式清理时可组合使用：

```powershell
& "<InstallRoot>\Uninstall.exe" /S /REMOVEASR /REMOVESETTINGS
```

`/REMOVETASKS` 会删除任务工作区和恢复缓存，`/REMOVECREDENTIALS` 会删除 CLI / Agent 共用的用户级 `auth.json`；两者不得作为无人值守卸载的隐式默认值。

### 受管 ASR 本地暂存验收

先构建受管 Whisper runtime 和 NVIDIA 组件，再用已校验模型生成隔离会话：

```powershell
.\scripts\build_whisper_components.ps1 -Json

$sessionRoot = Join-Path $env:TEMP "transvortex-managed-asr-e2e-large-v3"
.\scripts\stage_managed_asr_e2e.ps1 `
  -BuildManifest .\dist\asr-components\1.0.0\asr_components_build.json `
  -ModelId large-v3 `
  -ModelPath "C:\path\to\verified\faster-whisper-large-v3" `
  -SessionRoot $sessionRoot `
  -Json

python .\scripts\accept_managed_asr_staging.py `
  --stage-report "$sessionRoot\stage_report.json" `
  --pipeline-seed .\pipeline.desktop.yaml `
  --providers-seed .\providers.yaml `
  --output-report "$sessionRoot\managed_asr_acceptance.json"
```

如需证明已安装应用不依赖工作区 Python，在隔离目录安装内部 NSIS 包后，使用安装目录内置解释器重跑同一验收：

```powershell
$installRoot = "C:\path\to\installed\TransVortex"
& "$installRoot\runtime\python\python.exe" .\scripts\accept_managed_asr_staging.py `
  --stage-report "$sessionRoot\stage_report.json" `
  --pipeline-seed .\pipeline.desktop.yaml `
  --providers-seed .\providers.yaml `
  --output-report "$sessionRoot\managed_asr_installed_runtime_acceptance.json"
```

从该安装目录启动可见 APP，完成真实 ASR 任务、进入任务处理窗审看并重新导出后，在卸载前生成最终机器报告：

```powershell
& "$installRoot\runtime\python\python.exe" .\scripts\verify_managed_asr_app_e2e.py `
  --stage-report "$sessionRoot\stage_report.json" `
  --task-id "tvx_YYYYMMDD_HHMMSS_xxxxxx" `
  --installer ".\dist\installer\windows\TransVortex-setup-internal.exe" `
  --install-root $installRoot `
  --output "$sessionRoot\managed_asr_installed_app_e2e.json"
```

暂存脚本不修改产品 ASR 清单。2026-07-18 已完成本机安装目录的可见 APP 真实任务、审看、重新导出与卸载清理；这仍不等于公开下载或干净 Windows 验收。完整边界和现场证据见 [`LOCAL_ASR_COMPONENTS.md`](LOCAL_ASR_COMPONENTS.md) 与 [`archive/e2e-reports/2026-07-18-managed-asr-installed-app-e2e.md`](archive/e2e-reports/2026-07-18-managed-asr-installed-app-e2e.md)。

## 7. 人工桌面验收

启动检查：

```powershell
.\scripts\accept_flutter_release_manual.ps1 -LaunchCheck
```

完整真实窗口任务：

```powershell
.\scripts\accept_flutter_release_manual.ps1 -InputPath "DemoTest/英文视频.mp4"
```

人工确认范围：选择片源、提交、观察运行、完成或取消、打开结果、进入任务处理并审看结果。

需要复用工作区 ASR 环境时，应使用第 5 节的 APP E2E 脚本；直接运行本节脚本只使用当前 APP 数据目录中已经配置好的 runtime。

最终 Release Candidate 还必须在干净 Windows 环境重跑精简真实任务，并验证通知归属和点击聚焦。

## 8. 验证选择

- Python 小改：相关 pytest。
- Python 核心流程或跨模块改动：优先全量 `pytest -q`。
- Flutter UI 或 worker protocol：`flutter analyze` + `flutter test`。
- 主流程或发布布局：补 `flutter build windows` 和对应 release smoke。
- 安装器或 runtime：构建与安装器验收脚本。
- 凭据、provider、ASR 和翻译：对应最小测试，并在外部条件具备时跑真实服务 smoke。

无法执行的验证必须说明原因和剩余风险。
