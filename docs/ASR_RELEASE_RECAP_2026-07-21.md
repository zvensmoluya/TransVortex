# ASR 公开下载与安装体验复盘

日期：2026-07-21

这是一次临时现场复盘，正文集中记录本轮 faster-whisper 公开下载、安装器、卸载器和 Flutter 识别设置的观察。后续事项完成后，可将本文件归档或删除；产品长期边界仍以专题文档和 `CURRENT_BACKLOG.md` 为准。

## 现场结论

- Windows x64 的 faster-whisper runtime 已从公开 Release URL 下载，并按清单大小与 SHA-256 校验通过。
- 在全新的应用数据目录中下载 `small` 模型，安装后文件与固定 revision 一致。
- 下载后的受管 runtime 已在 CPU `int8` 下完成模型加载和本地转录探针。
- 最新内部 NSIS 安装包已生成，程序安装目录可以放在 D 盘；这不代表用户数据根也会自动迁移到 D 盘。
- 本轮验证通过的是后端安装管理器和本地探针；可见 Flutter 窗口中的点击安装、真实媒体任务和最终结果审看仍需单独完成。

## 路径语义

程序安装目录与用户数据目录是两条路径：

- 程序：用户在安装器中选择的 `TransVortex` 专用目录。
- 组件、模型、下载缓存、配置和任务：默认位于 `%LOCALAPPDATA%\TransVortex`。
- 临时验收可以通过 `TRANSVORTEX_HOME` 指向独立的 D 盘目录；普通用户界面目前还没有资源目录选择入口。
- 不应手动把组件目录搬进程序安装目录；如果要支持用户选择 D 盘，应实现独立的数据根设置和迁移语义。

## Flutter 识别设置观察

这些现象不代表 runtime 安装失败，而是设置页状态和产品表达需要收敛：

1. 安装 operation 进入终态后，页面仍保留完整进度条和“已完成”行。运行中显示进度；完成后应转为短暂结果提示；失败和取消才保留下一步动作。
2. operation 行增删后列表滚动位置没有复位，模型选择器和安装区域可能被截在中间。
3. 未发布的 NVIDIA 加速包仍显示灰色“安装”按钮。CPU-only 发布阶段应隐藏该动作，或明确显示“暂未开放”。
4. “组件已就绪”不能代替整条识别方案 readiness。runtime 已安装但默认模型缺失时，应明确提示还需要安装模型。
5. 选择 `small` 后仍显示已保存的 `large-v3` 默认方案属于草稿与已保存状态混在一起，界面需要更清楚地表达“尚未保存”。

## 安装器与卸载器观察

- NSIS 安装器先解压到 `<InstallDir>.__staging`，校验后再切换到正式目录；`.__previous` 用于升级回滚。这是原子替换保护，不是把工作区直接复制给用户。
- 当前内部安装器显示逐文件解压详情，会暴露 staging 路径和 DLL 名称。功能正常，但公开版本应隐藏内部路径，改成产品化的安装进度文案。
- 卸载只删除程序目录、快捷方式和卸载注册信息，默认保留用户配置、任务、组件和模型；当前没有“同时清理用户数据”的选项。
- 卸载不会把程序目录移动到回收站，而是直接删除受管安装目录；用户数据保留策略与此分开。

## 当前发布边界

- 首轮只把 faster-whisper CPU runtime 作为已发布能力。
- NVIDIA 加速包仍未发布，不应在界面上呈现为可执行安装动作。
- 模型按固定 upstream revision 下载，不打进基础安装包。
- Agent 入口暂不提前开发；它应在原生点击安装和可见 APP 真实任务通过后，复用同一套安装能力。

## 下一步顺序

1. 修复终态进度条、列表滚动、readiness 文案和未发布组件动作。
2. 用全新的 D 盘数据根，从可见 Flutter 窗口完成 `small + CPU` 的点击下载和真实媒体任务。
3. 决定是否提供普通用户可见的数据根选择，并补充迁移/清理语义。
4. 隐藏 NSIS 内部解压细节，完成安装器视觉和卸载说明的产品化。
5. 原生路线稳定后，再实现 Agent 的 apply/接力入口。
