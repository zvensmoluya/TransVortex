# Flutter 任务配置语义

本文记录主窗口参数从哪里来、作用于哪个任务、何时写入任务记录，以及继续任务时实际采用什么。它描述当前代码与已确认的产品边界，不把尚未实现的能力写成现状。

## 1. 三类片源

| 用户片源 | 当前输入 | worker 路径 | ASR 语义 | 当前证据 |
| --- | --- | --- | --- | --- |
| 视频 | MP4、MKV、MOV、AVI、WebM、FLV | `video_asr_translate` | Flutter 导入后调用 `media.inspect` 探测内嵌字幕；找到匹配字幕轨时写入 `source_mode=embedded_subtitle` 和轨道编号，不检查 ASR；否则写入 `source_mode=asr` 并检查识别准备状态 | Python 媒体探测测试、Flutter controller 测试和内嵌字幕 worker smoke 覆盖 |
| 音频 | MP3、WAV、M4A、FLAC、AAC、OGG | `video_asr_translate` | 必须使用 ASR，再进入翻译和字幕导出 | Flutter 已覆盖请求映射；尚缺独立音频端到端 smoke |
| 字幕 | SRT | `srt_translate` | 直接读取字幕并翻译，不使用 ASR，也不应因识别配置缺失而阻塞 | Python `test_srt_workspace.py` 和 Flutter controller 测试覆盖 |

ASS、WebVTT 和 LRC 当前能被前端识别为字幕文件，但作为输入会明确拒绝；它们目前是输出能力，不应表述成已支持输入。

## 2. 参数作用域

| 参数 | 新任务来源 | 导入前可改 | 创建任务时 | 新片源 / 新任务 | App 重启 | 继续任务 |
| --- | --- | --- | --- | --- | --- | --- |
| 片源 | 无默认值 | 通过选择或拖入绑定 | 写入 `input_file` 和 `input_type` | 更换片源会清空任务状态和临时输出目录 | 不恢复 | 沿用原任务片源 |
| 源语言 | 控制器默认 `auto` | 可以 | 写入任务记录 | 当前会话保留 | 重置为 `auto` | 从任务记录恢复 |
| 目标语言 | 控制器默认 `zh-CN` | 可以 | 写入任务记录 | 当前会话保留 | 重置为 `zh-CN` | 从任务记录恢复 |
| 翻译路由 | 用户选择；否则使用当前活动常用模型 | 可以 | 完整 routing 写入任务设置 | 当前会话显式选择继续保留 | 显式选择不恢复，重新读取活动常用模型 | 沿用原任务 routing |
| 思考程度 | 常用模型中主 route 的默认策略；主界面显示解析后的实际档位，选择浮层用“模型默认”标记表达内部 `auto` 状态 | 可以 | 写入主 route 的 `reasoning_effort`，随完整 routing 冻结 | 当前会话临时选择继续保留；切换到支持同一明确档位的模型时继续保留，否则回到新模型自身策略 | 临时选择不恢复，重新读取活动常用模型 | 沿用原任务 routing；fallback 使用各自冻结的策略 |
| 识别方案 | `pipeline.yaml` 当前默认方案 | 可以 | 音频和确实需要 ASR 的视频写入运行覆盖，任务创建后保存到 pipeline 设置快照 | 当前会话显式选择继续保留 | 显式选择不恢复，重新读取默认方案 | worker 沿用任务设置快照；SRT 和使用内嵌字幕的视频不适用 |
| 单语 / 双语 | 控制器默认双语 | 可以 | 写入任务记录 | 当前会话保留 | 重置为双语 | 从任务记录恢复；重新导出可另选 |
| 双语顺序 / 换行偏好 | 任务字幕样式快照 | 主窗口不公开 | 写入任务 pipeline 设置快照 | 不适用 | 重新读取任务或全局样式 | 重新导出可另选；成功后作为该任务最近交付方案保存 |
| 输出格式 | 控制器默认 SRT + ASS | 可以 | 写入任务 pipeline 设置快照 | 当前会话保留 | 重置为 SRT + ASS | worker 沿用任务设置快照；重新导出可另选 |
| 自动生成术语建议 | 控制器默认开启 | 可以 | 映射为 memory 生成相关覆盖并写入任务 pipeline 设置快照 | 当前会话保留 | 重置为开启 | worker 沿用任务设置快照 |
| 输出目录 | 默认片源所在目录 | 当前只在失败恢复中可改 | 计算成输出文件路径 | 更换片源时清空临时覆盖 | 不恢复 | 原任务工件目录和输出记录保持不变；重新导出可另选 |

这里的“当前会话保留”指同一个主窗口控制器存活期间保留，不代表用户偏好已经持久化。主窗口目前没有任务草稿偏好存储。

应用网络方式不属于任务参数。它作为用户级全局配置持久化，不写入任务快照；新任务、失败后重新启动的 worker 和继续任务都读取执行时的当前网络方式。修改网络设置不会改写任务保存的翻译 routing、识别方案或其它可复现参数。

## 3. 创建与继续

### 创建新任务

选择片源只更新本地草稿。只有点击“开始译制”才调用 `runtime.submitRun` 并创建任务。创建时，语言、单双语、routing 和 pipeline 覆盖会形成任务快照，供执行、复现和继续任务使用。

### 继续已有任务

继续任务是严格恢复：Flutter 只提交 `task_id`，后端读取原任务保存的 pipeline 和 routing 快照，再从未完成阶段继续。主窗口当前的新任务草稿，包括模型、格式、识别方案和术语开关，都不会改写旧任务。如果需要换模型重译，应在任务管理中创建一个新的重译任务，而不是继续旧任务。

## 4. 已确认规则

- SRT 直译跳过 ASR，不要求识别配置。
- 音频需要 ASR。
- 视频默认自动选择字幕来源，ASR 是没有可用内嵌字幕时的兜底，不是所有视频的固定第一步。
- 导入前显示的是当前会话的新任务草稿，不是已经持久化的用户默认值。
- 任务创建后以任务快照为复现和继续的基础。
- 继续任务只沿用原任务快照；修改模型、推理强度或目标语属于新的重译任务。
- “自动生成术语建议”只控制系统生成建议，不表示关闭已有人工术语的使用。
- 该开关只写入后端识别的 memory 生成覆盖；关闭时不写 `memory_enabled=false`，也不关闭 `memory_inject_enabled`。

## 5. 识别准备状态

Flutter 只使用后端返回的 `readiness.can_run` 判断识别方案能否执行，不再根据“是否需要密钥”推断。状态只使用四类：

- `ready`：当前方案可以执行。
- `needs_action`：需要安装组件或模型、选择并验证已有模型目录、配置凭据或完成连接测试。
- `checking`：组件下载、模型下载或硬件检查正在进行。
- `unavailable`：已有模型目录失效、服务不可达或硬件 / 计算精度不兼容。

本机 Whisper、OpenAI Whisper 和 FunASR 是三套独立方案，不自动回退。FunASR 需要最小音频连接测试；OpenAI Whisper 固定使用官方 Transcriptions 地址并独立检查用户凭据；本机 Whisper 始终使用受管运行组件，并检查模型来源、已有模型目录指纹和 NVIDIA 硬件。保存识别设置后，Flutter 会重新读取后端状态再更新主窗口，不做乐观“已配置”。

## 6. 待产品决策

1. 新任务语言、输出格式、单双语和术语生成选择是否要跨 App 重启持久化。
2. 是否在主窗口公开视频字幕来源模式：自动、强制 ASR、指定内嵌字幕；当前只公开自动判断。
3. 是否把 ASS、WebVTT 和 LRC 纳入字幕输入，而不只作为输出格式。
4. 输出目录是否作为常规任务参数公开，而不是只在失败恢复和重新导出时选择。

这些问题在决定前不阻塞当前主流程，但会影响后续任务设置、术语工作区和继续任务交互设计。
