# Flutter 产品表面与状态动作契约

本文档决定一项能力是否应该出现在普通用户界面、出现在哪里，以及当前状态允许什么动作。

任务参数的来源、作用域和片源类型差异见 `FRONTEND_TASK_CONFIGURATION_SEMANTICS.md`。

当界面归属与设计稿、测试入口或归档材料冲突时，以本文档为准。后端已经接线、测试已经覆盖，不自动等于该能力必须公开展示。

## 1. 当前产品表面

### 主窗口

只承载当前一次制作：

- 选择音频、视频或字幕片源。
- 选择本次任务的语言、翻译模型和输出形式；音频 / 视频任务还可选择识别方案，SRT 直译不显示识别步骤。
- 决定本次是否自动生成术语建议。
- 开始、停止或恢复当前任务。
- 展示当前任务的可信进度、失败恢复和完成结果。

主窗口不承载历史列表、深层设置、诊断报告、术语维护和完整结果编辑器。

### 任务处理窗

承载需要跨任务或需要较大工作面的任务操作：

- 查找历史任务，并按制作中、待处理、待校对、已完成和已取消筛选。
- 查看选中任务的摘要和事件。
- 继续可恢复任务或取消运行中任务。
- 审看、编辑和重新导出已完成结果。
- 在用户明确需要时打开任务目录或结果目录。

操作区必须由任务状态决定，只显示当前真正可用的主要动作。刷新属于列表级动作，不在任务详情重复出现。目录检查属于失败恢复或重新导出前的上下文动作，不常驻工具栏。

### 翻译模型设置窗

只负责准备可用的翻译连接和常用模型。普通界面不展示配置文件来源、`.env`、`env_key`、`credential_id` 等实现概念。凭据只表达为“已配置”或“需要配置”，开发兼容来源只能进入内部支持信息。

### 语音识别设置窗

只负责准备默认识别方案及其必要参数。三套方案保持独立，不自动切换：

- 本机 Whisper：始终使用 TransVortex 管理的隔离运行组件；模型既可由应用自动准备，也可由用户明确选择已有的兼容模型目录。
- FunASR：连接用户提供的服务，并通过最小音频请求确认可用。
- OpenAI Whisper：使用官方 Transcriptions 地址并独立读取用户级凭据。

受管本机 Whisper 分开显示运行组件、`small` / `medium` / `large-v3` 模型和可选 NVIDIA 加速包。下载过程提供进度、取消和失败重试；NVIDIA 包安装后必须实际检查 CUDA，明确选择 NVIDIA 时不得静默降级到 CPU。基础安装包携带通用媒体读写工具 FFmpeg，但不携带本机 Whisper runtime、模型或 NVIDIA / CUDA 包；后三者仍只在用户明确操作后按需下载。

“使用已有模型”通过系统目录选择器指定位置。应用使用受管运行组件检测模型规格并完成最小转录，只登记原目录和文件指纹，不复制、移动、删除或重新下载模型；目录失效或关键文件变化后要求重新验证。普通界面不发现或选择外部 Python，也不要求用户理解 Python、CTranslate2 或解释器路径。

进程内 `faster-whisper` 仍保留给 CLI 和开发实验，但 Flutter 全新配置不会创建该入口。环境缺失时给出与当前方案对应的修复动作，不展开完整 doctor 报告。

### 应用菜单与任务资料

主窗口应用菜单只提供翻译模型设置、语音识别设置和任务处理，不向普通用户暴露内部任务存储根。正式 Flutter 固定使用 Windows 用户级应用目录；仓库 `artifacts/` 只属于显式仓库 CLI 的开发 / 实验工作区，正式 Flutter 不扫描、不导入，也不为开发阶段任务承担兼容迁移。

任务处理窗提供“任务目录”“结果目录”和重新导出入口。ASR 文本、翻译状态和质量信息长期保存在任务目录；ffmpeg 音轨、WAV 分片、上传音频和细分重试文件进入应用 Cache，成功后清理，失败或取消时保留以支持恢复。最终字幕的输出目录仍由任务决定。

受管识别数据固定放在 `%LOCALAPPDATA%\TransVortex`：运行组件位于 `Components`，模型位于 `Models\faster-whisper`，断点下载和操作状态位于 `Downloads\ASR`。这些目录不进入任务工件，也不写入仓库配置。

### 托盘驻留与退出

- 关闭主窗口表示隐藏到系统托盘，不等于退出；Local Service 和当前任务继续运行。
- 关窗时同时收起工具窗和任务处理窗，避免留下失去主窗口上下文的孤立窗口。
- 如果任务处理窗存在未保存的字幕修改，收起主窗口或明确退出都会暂停关闭并前置该窗口；用户需要继续校对，或明确放弃修改后再关闭。
- 单击托盘图标或再次启动 TransVortex 会恢复已有主窗口，不创建第二套任务宿主；托盘菜单提供“打开 TransVortex”“任务处理”、当前任务状态和“退出 TransVortex”。
- 用户从托盘明确退出时，如果仍有制作中或排队任务，先选择“继续后台”或“取消任务并退出”。后者先请求取消相关任务，再关闭 Local Service 和应用进程。
- 托盘原生能力初始化失败时，不拦截窗口关闭，避免应用进入既没有窗口也没有托盘入口的状态。

## 2. 不公开的能力

### 内部诊断

现有 doctor、诊断窗口和 release smoke 继续保留，供开发、测试和支持定位问题使用，但不再出现在普通用户菜单中。

用户遇到问题时，应在失败发生的位置看到具体原因和恢复动作。只有未来形成完整、用户可理解的环境修复流程后，才重新评估是否需要公开诊断工具。

### 术语维护

以下能力作为一个整体延期，不逐个添加入口：

- 使用已有术语。
- 选择预设术语表。
- 查看和编辑自动生成的术语建议。
- 把建议转为受保护的人工术语。
- 跨任务复用、合并和维护术语。

在“生成、审看、保护、复用、注入翻译”的生命周期确定前，主窗口只保留“自动生成术语建议”。这个开关不表示是否使用已有术语，也不会关闭人工术语表。

## 3. 主窗口状态动作

| 状态 | 主要信息 | 主动作 | 次要动作 |
| --- | --- | --- | --- |
| 空 | 当前会话的新任务草稿，以及音频、视频或字幕片源入口 | 选择片源 | 调整新任务参数；恢复未完成任务（存在时） |
| 就绪 | 片源和本次任务方案 | 开始制作 | 更换片源 |
| 受阻 | 当前缺少的翻译或识别准备 | 去配置 | 更换片源 |
| 制作中 | 九阶段生产轨迹、真实进度、分窗/分片计数、累计模型请求和当前恢复动作 | 取消任务 | 无 |
| 失败 | 一句话原因和对应修复方向 | 重试、继续或去配置 | 打开任务处理（需要上下文时） |
| 完成 | 结果已经可处理 | 审看结果 | 打开字幕、打开目录、制作新片源 |

完成态不能把“制作新片源”放在结果处理之前。失败态不能把诊断报告作为默认恢复入口。

失败恢复以结构化错误码、失败阶段和任务检查点为准，不从原始英文错误猜动作。翻译或识别的配置 / 凭据问题分别直达对应设置；瞬时服务故障优先继续检查点或重试；取消和重新导出失败只能重试原操作。普通界面不得显示 `.env`、`env_key`、`task_id`、日志文件名或 Python 依赖等实现概念。

## 4. 任务处理状态动作

| 任务状态 | 主要动作 | 辅助动作 |
| --- | --- | --- |
| 制作中 | 取消任务 | 打开任务目录 |
| 可恢复失败或中断 | 继续任务 | 打开任务目录 |
| 不可恢复失败 | 无通用主动作；展示具体修复方向 | 打开任务目录 |
| 已完成且有质量 / 交付提醒 | 编辑字幕，先看有问题片段 | 打开结果目录、打开任务目录 |
| 已完成且修改已保存但未导出 | 编辑字幕，完成重新导出 | 打开结果目录、打开任务目录 |
| 已完成且检查通过 | 编辑字幕 | 打开结果目录、打开任务目录 |
| 已取消 | 有可恢复检查点时继续任务，否则无 | 打开任务目录 |

不可用动作不占据工具栏位置。任务详情不重复列表级刷新。仅在重新导出失败、输出缺失或目录不可写时显示目录检查与更换目录。

历史任务的配置型失败在失败线索旁提供对应设置入口；如果任务同时可以继续，先修复配置，再由“继续任务”复用原检查点，不用当前新任务草稿覆盖旧任务参数。

历史任务因输出目录不可写而失败时，选择新目录后直接重新导出；输出结果被移动或删除时可以原地重新导出。两种动作都优先复用该任务最近一次成功交付的输出格式、单双语、双语顺序和换行偏好，不读取当前主窗口的新任务草稿。

“待校对”收纳已经完成但最终质量状态、残留问题、交付检查仍有提醒，或字幕修改已经保存但尚未重新导出的任务；不使用已经被自动修复的历史问题计数。进入有质量问题的任务后首次默认聚焦“有问题”片段；用户仍可切回全部片段。

结果编辑把内容保存和文件交付分成两个明确阶段：保存更新任务里的结构化字幕片段，并重新评估人工修改后的质量问题，但不再次自动合并字幕或自动移动时间轴；重新导出才更新 SRT、ASS、VTT 或 LRC 文件并刷新交付检查。用户可以修改译文和开始 / 结束时间，时间码支持直接输入与 0.1 秒微调；空值、格式错误、负时间或结束不晚于开始会留在当前片段并阻止保存，合法但与相邻字幕重叠的时间仍允许保存，由更新后的质量检查继续标记。工作区持续显示“未保存”“已保存待导出”“导出中”“已交付”或“导出失败”，操作失败时保留当前字幕和恢复动作。问题导航在所有问题片段间循环并固定当前片段边签，时间相关问题同时展开校时控件；修完当前筛选中的最后一条问题后回到全部片段，不让刚保存的结果从视野中消失。重新导出允许复核格式、单双语、双语顺序和“尽量单行”，这些选择成功后成为该任务下一次恢复导出的基线。

## 5. 实施规则

- 新增用户入口前，先在本文档中确认归属和公开状态。
- “后端已支持”不能作为新增菜单、按钮或页面的充分理由。
- 文案描述用户意图，不描述内部子系统开关。
- 一项能力如果还没有清楚的成功路径、失败路径和数据归属，就保持隐藏。
- 每轮只重做一个完整工作流，并在真实 Windows release 窗口中验收。
