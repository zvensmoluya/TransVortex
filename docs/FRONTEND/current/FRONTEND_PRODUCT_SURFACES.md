# Flutter 产品表面与状态动作契约

本文档决定一项能力是否应该出现在普通用户界面、出现在哪里，以及当前状态允许什么动作。

任务参数的来源、作用域和片源类型差异见 `FRONTEND_TASK_CONFIGURATION_SEMANTICS.md`。

当界面归属与设计稿、测试入口或归档材料冲突时，以本文档为准。后端已经接线、测试已经覆盖，不自动等于该能力必须公开展示。

## 1. 当前产品表面

### 主窗口

只承载当前一次制作：

- 选择音频、视频或字幕片源。
- 选择本次任务的语言、翻译模型和输出形式；音频 / 视频任务还可选择识别方案，SRT 直译不显示识别步骤。
- 决定本次是否自动生成术语建议。
- 开始、停止或恢复当前任务。
- 展示当前任务的可信进度、失败恢复和完成结果。

主窗口不承载历史列表、深层设置、诊断报告、术语维护和完整结果编辑器。应用设置可以作为同一原生窗口的右侧扩展面同时出现，但左侧 `720 x 520` 任务工作面保持固定，不缩放、不回流，设置内容也不混入本次任务表单。

### 任务处理窗

承载需要跨任务或需要较大工作面的任务操作：

- 查找历史任务，并按制作中、待处理、待校对、已完成和已取消筛选。
- 查看选中任务的摘要和事件。
- 继续可恢复任务或取消运行中任务。
- 审看、编辑和重新导出已完成结果。
- 在用户明确需要时打开任务目录或结果目录。

操作区必须由任务状态决定，只显示当前真正可用的主要动作。刷新属于列表级动作，不在任务详情重复出现。目录检查属于失败恢复或重新导出前的上下文动作，不常驻工具栏。

### 翻译模型设置窗

负责准备可用的翻译连接、常用模型和应用全局网络方式。连接详情自动尝试获取上游模型目录，并把“上游可用模型”与持久化的“已启用模型”分开；用户从发现结果明确启用模型，也可以在上游不支持列表接口时手动添加模型 ID。常用模型为主模型和每个备用模型保存默认思考程度，入口收在模型行内；主窗口把当前任务的临时覆盖收在翻译模型菜单内，最终选择进入任务 routing 快照。连接详情只为当前模型提供不持久化的测试档位，并让连接测试真实携带该值。网络页签只提供“跟随系统”“直连”“本地代理”三种选择；本地代理固定连接 `127.0.0.1`，用户只填写代理软件的 HTTP / Mixed 端口。同一全局设置也在应用设置的“网络”分类提供，两处共用状态、校验和保存契约。该设置同时作用于翻译模型、远程识别和受管组件下载，不按连接重复配置；本地服务请求始终绕过代理。

Base URL 表示模型 API 或中转网关地址，不表示本机网络代理。普通界面不展示配置文件来源、`.env`、`env_key`、`credential_id` 等实现概念。凭据只表达为“已配置”或“需要配置”，开发兼容来源只能进入内部支持信息。

### 语音识别设置窗

只负责准备默认识别方案及其必要参数。三套方案保持独立，不自动切换：

- 本机 Whisper：始终使用 TransVortex 管理的隔离运行组件；模型既可由应用自动准备，也可由用户明确选择已有的兼容模型目录。
- FunASR：连接用户提供的服务，并通过最小音频请求确认可用。
- OpenAI Whisper：使用官方 Transcriptions 地址并独立读取用户级凭据。

受管本机 Whisper 分开说明运行组件、`small` / `medium` / `large-v3` 模型和可选加速能力，但首轮设置不要求用户逐项管理组件。用户选择模型来源、模型与运算方式后，以一次“下载并启用”任务顺序完成缺失运行组件、模型下载、校验和方案保存；同一时间只允许一个 ASR 设置任务。重复发起同一任务返回已有任务，不同任务在当前任务结束前不得进入隐式并行或后台锁等待。

设置任务运行时占据窗口主状态，配置表单收为摘要；界面显示稳定的任务名称、当前阶段、真实字节进度和取消终态。关闭设置窗表示任务继续在 Local Service 中运行，托盘必须显示对应状态，重新打开设置窗自动接回同一任务。从托盘明确退出应用时先请求取消并等待任务进入终态。取消、网络失败或进程中断不得激活半成品目录；已经校验的文件和断点下载可以保留并在重试时复用，界面必须明确说明这一点。

首轮公开能力只提供 CPU 设置路径。NVIDIA 驱动与 CUDA 用户态依赖不作为可点击安装项；未开放时不在主要设置流程显示灰色动作。基础安装包携带通用媒体读写工具 FFmpeg，但不携带本机 Whisper runtime 或模型；runtime 由 TransVortex 公开资产提供，模型直接从固定 upstream revision 获取，也可以验证并原地使用已有模型目录。

“使用已有模型”把目录选择理解为“查找位置”：用户既可以选择模型目录本身，也可以选择包含模型的上层目录。应用在受限的深度和目录数量内查找候选；只找到一个时直接选中，找到多个时显示可读的相对位置和大小供用户选择。查找结果只代表目录结构可能兼容，不能直接启用。

应用随后使用受管运行组件真实加载所选模型并完成最小转录，通过后才登记原目录和关键文件指纹，不复制、移动、删除或重新下载模型；目录失效或关键文件变化后要求重新验证。应用自动下载的模型仍按固定 revision 和逐文件哈希严格校验；用户已有模型不要求与官方配置哈希完全相同，未知但实际可加载的模型登记为“自定义 Whisper”，与官方配置相符的模型也只标为“兼容”规格，不宣称来源或识别质量。该路径支持转换为 faster-whisper / CTranslate2 格式的微调模型，不直接接受原始 PyTorch 模型目录。普通界面不发现或选择外部 Python，也不要求用户理解 Python、CTranslate2 或解释器路径。

进程内 `faster-whisper` 仍保留给 CLI 和开发实验，但 Flutter 全新配置不会创建该入口。环境缺失时给出与当前方案对应的修复动作，不展开完整 doctor 报告。

语音识别设置同时提供受管资源管理入口，让用户在当前识别上下文中直接删除 TransVortex 下载的运行组件、模型或未来的加速组件。用户自行选择并原地使用的模型不属于应用资产，不显示在清理列表中，也不会被应用删除。

### 应用设置扩展面

应用设置只承载软件级设置，使用紧凑分类切换而不是把所有内容平铺在一个长页面。当前提供“网络”和“存储与资源”：网络分类编辑应用全局连接方式及本地 HTTP / Mixed 代理端口；存储与资源分类显示受管识别资源的位置、磁盘空间和已安装资源，并允许在资源下载前更改位置或逐项删除 TransVortex 下载的资源。位置入口不能因为已有资源而消失；不能迁移时保持禁用并解释需要先删除受管资源。删除当前使用的运行组件或模型前必须说明后果；删除后识别方案可以变为未就绪，但用户自己的模型目录、配置、任务和凭据不受影响。

应用设置与翻译模型设置可以呈现同一全局网络能力，应用设置与语音识别设置也可以呈现同一资源管理能力；重复入口都使用同一 Local Service 状态和写入契约，但彼此不要求跳转。资源列表在打开、资源操作和服务快照变化后自动同步，正常流程不提供“刷新”动作；首次同步失败时才提供重试。应用设置不包含翻译连接、常用模型、识别方案等业务设置，也不作为所有设置的总路由。

宽屏上，打开时同一 HWND 从 `720 x 520` 一次性扩到 `1200 x 520`，右侧 `480 x 520` 绘制应用设置；关闭时先完成面板内容动画，再恢复原生窗口尺寸。不对原生宽度做逐帧动画。显示器可用宽度小于 `1200` 时，改用 `720 x 520` 窗口内的右侧覆盖层，关闭后不保留透明点击区。

### 应用菜单与任务资料

主窗口应用菜单分别提供翻译模型设置、语音识别设置、任务处理和应用设置。每个入口按用户当前目的独立打开，不通过“全部设置”聚合。应用设置在主窗口同一 HWND 内扩展；翻译与识别继续使用各自工具窗，任务处理继续使用独立工作台。工作数据根在安装时单独选择，运行中仍通过任务目录和结果目录等产品概念呈现。配置和凭据固定使用 Windows 用户级目录；仓库 `artifacts/` 只属于显式仓库 CLI 的开发 / 实验工作区，正式 Flutter 不扫描、不导入，也不为开发阶段任务承担兼容迁移。

任务处理窗提供“任务目录”“结果目录”和重新导出入口。ASR 文本、翻译状态和质量信息长期保存在任务目录；ffmpeg 音轨、WAV 分片、上传音频和细分重试文件进入应用 Cache，成功后清理，失败或取消时保留以支持恢复。最终字幕的输出目录仍由任务决定。

受管识别数据默认放在 `%LOCALAPPDATA%\TransVortex`：运行组件位于 `Components`，模型位于 `Models\faster-whisper`，断点下载和操作状态位于 `Downloads\ASR`。首次下载前，用户可以为这三类大文件选择另一个本地专用文件夹；配置、任务和凭据不随之移动。界面同时显示预计下载量和目标盘可用空间，后端在任务真正开始前按同一安全余量再次校验。已有受管资源或下载断点时，首版禁止直接切换位置，不做没有进度、校验和回滚的隐式跨盘搬运；已有模型的原地使用不受该设置影响。存储位置只写入用户级 `Config/asr_storage.json`，不进入 Provider YAML 或仓库配置。

### 托盘驻留与退出

- 关闭主窗口表示隐藏到系统托盘，不等于退出；Local Service 和当前任务继续运行。
- 关窗时先隐藏主窗口，再在不可见状态下收起应用设置并恢复 `720 x 520`；同时收起翻译、识别和任务处理等独立窗口，避免留下失去主窗口上下文的孤立窗口。
- 如果任务处理窗存在未保存的字幕修改，收起主窗口或明确退出都会暂停关闭并前置该窗口；用户需要继续校对，或明确放弃修改后再关闭。
- 单击托盘图标或再次启动 TransVortex 会恢复已有主窗口，不创建第二套任务宿主；托盘菜单提供“打开 TransVortex”“任务处理”、当前任务状态和“退出 TransVortex”。
- 用户从托盘明确退出时，如果仍有制作中或排队任务，先选择“继续后台”或“取消任务并退出”。后者先请求取消相关任务，再关闭 Local Service 和应用进程。
- 托盘原生能力初始化失败时，不拦截窗口关闭，避免应用进入既没有窗口也没有托盘入口的状态。

## 2. 不公开的能力

### 内部诊断

现有 doctor、诊断窗口和 release smoke 继续保留，供开发、测试和支持定位问题使用，但不再出现在普通用户菜单中。

用户遇到问题时，应在失败发生的位置看到具体原因和恢复动作。只有未来形成完整、用户可理解的环境修复流程后，才重新评估是否需要公开诊断工具。

### 术语维护

以下能力作为一个整体延期，不逐个添加入口：

- 使用已有术语。
- 选择预设术语表。
- 查看和编辑自动生成的术语建议。
- 把建议转为受保护的人工术语。
- 跨任务复用、合并和维护术语。

在“生成、审看、保护、复用、注入翻译”的生命周期确定前，主窗口只保留“自动生成术语建议”。这个开关不表示是否使用已有术语，也不会关闭人工术语表。

## 3. 主窗口状态动作

| 状态 | 主要信息 | 主动作 | 次要动作 |
| --- | --- | --- | --- |
| 空 | 当前会话的新任务草稿，以及音频、视频或字幕片源入口 | 选择片源 | 调整新任务参数；恢复未完成任务（存在时） |
| 就绪 | 片源和本次任务方案 | 开始制作 | 更换片源 |
| 受阻 | 当前缺少的翻译或识别准备 | 去配置 | 更换片源 |
| 制作中 | 九阶段生产轨迹、真实进度、分窗/分片计数、累计模型请求和当前恢复动作 | 取消任务 | 无 |
| 失败 | 一句话原因和对应修复方向 | 重试、继续或去配置 | 打开任务处理（需要上下文时） |
| 完成 | 结果已经可处理 | 审看结果 | 打开字幕、打开目录、制作新片源 |

完成态不能把“制作新片源”放在结果处理之前。失败态不能把诊断报告作为默认恢复入口。

失败恢复以结构化错误码、失败阶段和任务检查点为准，不从原始英文错误猜动作。翻译或识别的配置 / 凭据问题分别直达对应设置；瞬时服务故障优先继续检查点或重试；取消和重新导出失败只能重试原操作。普通界面不得显示 `.env`、`env_key`、`task_id`、日志文件名或 Python 依赖等实现概念。

## 4. 任务处理状态动作

| 任务状态 | 主要动作 | 辅助动作 |
| --- | --- | --- |
| 制作中 | 取消任务 | 打开任务目录 |
| 可恢复失败或中断 | 继续任务 | 打开任务目录 |
| 不可恢复失败 | 无通用主动作；展示具体修复方向 | 打开任务目录 |
| 已完成且有质量 / 交付提醒 | 编辑字幕，先看有问题片段 | 打开结果目录、打开任务目录 |
| 已完成且修改已保存但未导出 | 编辑字幕，完成重新导出 | 打开结果目录、打开任务目录 |
| 已完成且检查通过 | 编辑字幕 | 打开结果目录、打开任务目录 |
| 已取消 | 有可恢复检查点时继续任务，否则无 | 打开任务目录 |

不可用动作不占据工具栏位置。任务详情不重复列表级刷新。仅在重新导出失败、输出缺失或目录不可写时显示目录检查与更换目录。

历史任务的配置型失败在失败线索旁提供对应设置入口；如果任务同时可以继续，先修复配置，再由“继续任务”复用原检查点，不用当前新任务草稿覆盖旧任务参数。

历史任务因输出目录不可写而失败时，选择新目录后直接重新导出；输出结果被移动或删除时可以原地重新导出。两种动作都优先复用该任务最近一次成功交付的输出格式、单双语、双语顺序和换行偏好，不读取当前主窗口的新任务草稿。

“待校对”收纳已经完成但最终质量状态、残留问题、交付检查仍有提醒，或字幕修改已经保存但尚未重新导出的任务；不使用已经被自动修复的历史问题计数。进入有质量问题的任务后首次默认聚焦“有问题”片段；用户仍可切回全部片段。

结果编辑把内容保存和文件交付分成两个明确阶段：保存更新任务里的结构化字幕片段，并重新评估人工修改后的质量问题，但不再次自动合并字幕或自动移动时间轴；重新导出才更新 SRT、ASS、VTT 或 LRC 文件并刷新交付检查。用户可以修改译文和开始 / 结束时间，时间码支持直接输入与 0.1 秒微调；空值、格式错误、负时间或结束不晚于开始会留在当前片段并阻止保存，合法但与相邻字幕重叠的时间仍允许保存，由更新后的质量检查继续标记。工作区持续显示“未保存”“已保存待导出”“导出中”“已交付”或“导出失败”，操作失败时保留当前字幕和恢复动作。问题导航在所有问题片段间循环并固定当前片段边签，时间相关问题同时展开校时控件；修完当前筛选中的最后一条问题后回到全部片段，不让刚保存的结果从视野中消失。重新导出允许复核格式、单双语、双语顺序和“尽量单行”，这些选择成功后成为该任务下一次恢复导出的基线。

## 5. 实施规则

- 新增用户入口前，先在本文档中确认归属和公开状态。
- “后端已支持”不能作为新增菜单、按钮或页面的充分理由。
- 文案描述用户意图，不描述内部子系统开关。
- 一项能力如果还没有清楚的成功路径、失败路径和数据归属，就保持隐藏。
- 每轮只重做一个完整工作流，并在真实 Windows release 窗口中验收。
