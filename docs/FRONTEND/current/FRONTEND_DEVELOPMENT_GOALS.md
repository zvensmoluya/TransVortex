# TransVortex 前端开发 Goal

本文档以总工程师视角，给出 TransVortex 桌面前端的开发目标（Goal）。

它不按短期 / 中期 / 长期划分，不以工作量或打包体积为约束。每个 Goal 是一条必须达成的标准，配「现状差距」和「达成标准（验收）」。达成标准是硬验收，不是建议。

主轴（本版核心）：

> TransVortex 前端首先是一个**原生桌面 App**。严禁一切 web 感和 web 开发直觉。

世界隐喻（如「译制小屋」）是**可探索的候选**，不是脊梁。任何风格方向都必须服从 App 感主轴与下方禁令，否则不予采用。

上位约束：

- `rules/FRONTEND_FAILURE_RECOVERY_RULES.md`：禁令与停止条件。任一 Goal 不得与之冲突。
- `current/FRONTEND_POSITIVE_DESIGN_DIRECTION.md`、`current/FRONTEND_MAIN_SCREEN_STYLE_FRAME.md`：方向与对象**候选**素材，可借用、可推翻，不作为锁定规格。

## 0. 北极星

> 这是一个自绘的原生桌面客户端工作面，不是一个网页。

判定基线：任何一屏，去掉产品名后：

- 必须像一个**固定的原生 App 工作面**。
- 不得像后台、SaaS、配置台、剪辑软件、开发面板、普通网页。
- 不得让人看出它是 React/HTML/CSS/浏览器开发出来的。

设计意向高于工程惯性。讨论一旦从「这一屏作为 App 的手感对不对」滑向「这个 section 放哪、这个组件怎么复用、这个 token 怎么命名」，方向即偏。

## 1. 现状基线（Goal 要解决的真实问题）

记录在案，作为各 Goal 的对照锚点。引用为当前主分支实现。

App 感 / 结构：

- 主窗口是 820×560 内 `position:absolute` + 手调 px 堆叠，分区包围盒互相穿插，已存在真实碰撞：`.core-caption` 与 `.option-console` 在 x[422–514] y[376–396] 重叠；完成态 `.core-side-actions` 与 `.task-spool` 在 x[690–758] y[396–414] 重叠；`.source-cradle` 与 `.operation-core` 盒子咬合。
- 文本无约束。`.source-ticket strong` 长文件名 `overflow:hidden` 且无省略号，齐根裁切。
- 残留 web 开发直觉：`app/router.tsx` 仍以 `window.history.pushState` + URL path + 导航清单组织（虽未走活路径）；拖拽存在 DOM `filePathFromBrowserDrop` 死分支；几乎所有可点元素 `cursor:default`，无 App 级输入（快捷键 / 右键 / 焦点管理）。

配置窗口：

- 两个配置子窗口（`translation-config` / `recognition-config`）当前难看且不可用。
- `.socket-rack` 用 `overflow:auto` 滚动承载多服务卡片列表，触碰准则第 9 条，且结构本质是换皮的「provider 配置台」——典型 web 直觉。

设计世界：

- 实现自创了一套互不相干的萌系母题（礼物盒 / 魔法挂件 / 笑脸轨道 / 缝纫线轴），不是一个收敛世界。
- `prototypes/` 里已备好的世界对象 PNG 未被采用。

排版与设计系统：

- 大量无效精细字重（950 / 930 / 880 / 820 / 760 …）。当前绑定字体只有有限档位，全部塌平为「粗 / 不粗」，靠字重做的层级是假的。
- 多处 10px 中文，低于中文舒适阅读下限。
- 圆角无阶梯（10/12/13/14/15/18/24/28 及多种非对称值）；token 双轨（局部变量与全局 `styles/tokens.css` 并存且部分失效）。

状态可信度：

- 进度环显示假百分比：`progressFor` 给 ready=12%、canceling=76%、failed=66%；失败画成 2/3 满，误导为「快完成」。
- 中央状态图形是萌团子笑脸；失败 / 阻塞仍在笑，只加小感叹号。
- 状态主要靠极小色块（27×9px `.service-lamp`）纯色编码，对色盲不友好。
- 质量开关无 on 态视觉，三个并排拨片里两个有态一个无态，不一致。

资产：

- 同排对象一边内联 SVG、一边 1.4–1.5MB PNG，矢量 / 位图质感不一致且体积异常。
- 语义变色靠 `hue-rotate(135deg/96deg)` 硬转 PNG 色相表达 blocked/done，脆且非设计选定色。

能力覆盖与工程结构：

- 旧 Web 前端整棵树（`app/router.tsx`、`app/layout/*`、8 个 `*Page`、若干 `components/*`）已无人引用却仍被 `tsc` 编译，仍拉 `lucide-react`。
- 术语管理、环境诊断、任务历史、任务详情 / 事件、结果审看、导出设置在新界面无入口，对应旧页面成孤儿，当前产品内不可达。

## 2. App 感 vs Web 感（核心验收清单）

这是本 Goal 的脊梁。下表每条都可直接当验收项逐条过。

### 严禁：web 开发直觉的泄漏

- 布局：文档式纵向滚动、长页面、大块 `overflow:auto`；响应式 / 断点 / `vw` `vh` / 随窗口回流；header + nav + sidebar + footer 框架；卡片网格、面板墙、section 堆叠。
- 交互：链接式跳转导航；hover 才显形当主交互；表单提交心智（满屏表单 + 到处「保存」）；`position:fixed + backdrop + z-index` 当默认弹窗；全局可选中文本；默认浏览器焦点框、默认滚动条、非文本区出现文本光标。
- 窗口：一个大窗口干所有事（SPA 心智）；不用系统原生文件 / 目录 dialog；不用真正的子窗口 / 工具窗。
- 视觉：通用组件库观感（Material / AntD / Bootstrap）、通用图标库决定气质；扁平卡片 + 阴影那套 web 审美；spinner / 骨架屏式「加载中」。
- 手感：首帧空白再 pop-in、FOUC、懒加载分块闪烁、布局位移、过场松垮。

### 要求：App 感

- 一个稳定、固定、不回流的工作面，分区被刻意框定，不随内容 / 窗口流动。
- 直接操作：拖文件进来、拖动对象、点的是「物件」不是「链接」；状态即时生效，无提交仪式。
- 真窗口模型：主窗口 + 专用工具窗 / inspector（配置就是它自己的窗口）；文件 / 目录走系统原生 dialog；自绘标题栏但行为像原生（拖拽区、最小化 / 关闭、固定尺寸不给最大化）。
- App 级输入：键盘快捷键、明确焦点管理、控件级 tooltip / 右键菜单。
- 紧、准、稳：工具级密度（不是营销页大留白）；无布局抖动；过场短促有目的；内容是「已经在那」而不是「正在加载」。
- 自绘、专属的视觉语言，不被组件库 / 图标库绑架。

## 3. Goal

### G1 — App 工作面骨架与窗口模型

目标：主窗口是固定客户端工作面；产品由真窗口模型组织，而非单页 web 应用。

现状差距：见 §1 App 感 / 结构。

达成标准：

- 主窗口无页面路由、URL path、`window.history`、刷新或路径跳转；无纵向滚动文档、无大块 `overflow:auto`、无响应式 / `@media` / `vw` `vh`。
- 自绘标题栏行为对齐原生：拖拽区、最小化 / 关闭，固定尺寸不给最大化。
- 文件 / 目录选择走系统原生 dialog。
- 任务详情、配置、诊断、修复、高级设置优先以真实子窗口 / 固定 inspector / 工具窗 / 任务状态呈现，**不得**做成主窗口内嵌网页 modal（`position:fixed + backdrop + z-index`）。

### G2 — 设计世界（开放探索，受约束）

目标：建立一个连贯、自洽、有现实来源的单一世界；隐喻开放，但必须服务 App 感且不重新引入 web 感。

现状差距：见 §1 设计世界。当前是萌物拼盘。

达成标准：

- 屏上对象构成**一个**世界，不是互不相干的母题拼盘；对象不是从功能目录 / 配置项 / 表格 / 面板推导出来的。
- 截图去掉产品名后，被独立观察者判定为某个具体可信的 App，而非后台 / 配置台 / 剪辑软件 / 网页。
- 世界隐喻可换、可推翻，但每次更换都要整屏一致，不允许新旧母题混搭。
- 少女助手为可选项，不作为硬要求；若采用，不得遮挡主操作、不得退化为常驻看板娘或导航。
- 文案亲切但不过度卖萌；世界观词在同处保留清楚解释。

### G3 — 配置：主从式偏好工具窗

目标：把「确实复杂」的配置承载为一个原生偏好窗（master-detail），而非滚动卡片流。

现状差距：见 §1 配置窗口。当前两窗难看不可用，且是滚动 provider 卡片台。

达成标准：

- 配置为专用工具窗，尺寸可与主窗口不同（允许更高 / 更大的固定尺寸）。
- 采用主从结构：一侧固定列出服务 / 能力，一次只选一个；另一侧是稳定详情面板，只编辑当前选中项。切换靠选择，**不靠把卡片堆成长流滚动**。
- 不出现 `overflow:auto` 的卡片列表作为主体；不出现 provider 表格直铺；不是覆盖主窗口的网页 modal。
- 分层清晰：主屏只承载当前方案的高频摘要与常用切换（以世界对象形态，非表格 / 面板）；provider endpoint、API key、request/response mapping、routing fallback、ASR 地址 / chunking / 静音检测、并发 / 超时 / 重试、CPS、ASS 字体描边边距、memory 细项等进偏好窗的详细面板。
- ASR / 翻译 / 术语作为「方案能力」出现，而非并列后台模块；跨窗口同步与持久化语义一致且明确（不得一个落盘一个仅改内存草稿而界面对称）。

### G4 — 确定性布局，零碰撞、零意外裁切

目标：以确定性的区域布局（区域内 grid / flow，而非整屏手摆 px）组织固定工作面；任何内容下元素包围盒不重叠。

现状差距：见 §1 App 感 / 结构。已有多处真实碰撞与无省略号裁切。

达成标准：

- 在最坏内容下（最长文件名、最长模型 id、最长错误文案、3 条运行中任务、最长目录名同时出现）验证：无任何元素重叠，无被裁切且无省略号的文本。
- 每个文本位有定义好的最大宽 / 高与降级规则（单行省略号或受控换行），并在验证集实测。
- 固定尺寸不可缩放，但内部布局对内容长度稳健。
- 主操作是明确视觉主角，装饰不得在尺寸 / 亮度 / 居中度上压过主 CTA。

### G5 — 设计系统与字体

目标：建立并强制使用一套真实 token 阶梯；层级靠字号、字重、颜色、间距实现，全部有效。

现状差距：见 §1 排版与设计系统。无效精细字重、10px 中文、圆角动物园、token 双轨。

达成标准：

- 打包一套带真实多档字重的字体（随桌面客户端分发，打包体积不作约束）；所有字重值都能真实渲染出对应档位，不存在塌平的精细字重。
- 中文正文不低于约定下限（建议正文 ≥12px，主要信息 ≥13–14px），无 10px 中文承载有效信息。
- 圆角、间距、颜色取自有限 token 集；删除 / 归并失效的全局 token 与局部变量，单一事实来源。
- 颜色控制比例：大面积暖白 / 柔底、深紫灰文字、莓粉主强调、汽水蓝辅助、布丁黄提醒、低饱和绿仅成功态；避免赛博 / 大面积紫蓝渐变 / 霓虹。
- 输出一份简明设计系统说明（本目录），列最终阶梯值，供实现与审查对照。

### G6 — 可信状态表达

目标：状态可信、可理解、失败可懂；不依赖单一颜色。

现状差距：见 §1 状态可信度。假进度、笑脸失败、纯色小灯、质量无态。

达成标准：

- 进度只反映真实进度；无真实进度的状态（ready / blocked / failed / canceling）不得用部分填充进度环伪造百分比。
- 失败 / 阻塞在形态上与「接近完成」明确可分，不得以微笑 / 萌化形象承载；失败给出明确恢复动作。
- 状态用 形状 + 颜色 + 文字 三重冗余，灰度下仍可区分；无纯色编码的关键状态。
- 每个开关 / 多态控件在任一状态都有一致、可一眼读出的视觉态。

### G7 — affordance、App 级输入与可达性

目标：每个可交互对象都看得出能交互；具备 App 级输入与键盘可达。

现状差距：见 §1。`cursor:default` 遍布，无快捷键 / 右键 / 焦点管理，拖拽落点反馈弱。

达成标准：

- 可交互对象具备 hover / active / focus-visible / disabled 四态；可点击对象（含插画型）光标与反馈表明可操作。
- 提供合理键盘 Tab 顺序与可见焦点；为高频动作提供快捷键；为合适对象提供右键菜单 / 控件级 tooltip。
- 拖拽落点在 drag-over 时给出全区域、明确「往这里放」反馈，而非小幅位移。
- App chrome 区域不可选中文本；自绘焦点环与滚动条，不暴露浏览器默认样式。

### G8 — 视觉资产规范与一致性

目标：统一资产法则，世界对象资产风格、技术形态、状态变色方式一致。

现状差距：见 §1 资产。SVG / 位图混用、3MB 大图、`hue-rotate` 假变色。

达成标准：

- 同一角色 / 同组并列对象不得混用矢量与位图；统一矢量，或统一经校验的透明 PNG。
- 世界对象图片按 `FRONTEND_IMAGE_ASSET_GENERATION.md` 校验 alpha 通道后才能进原型。
- 资产按实际显示分辨率出图（高清屏至多 ×2）；打包体积不约束，但**运行时**不得因超大位图造成解码 / 合成卡顿（见 G10）。
- 语义变色用真实图层 / tint token 实现，禁止 `hue-rotate` 等色相硬转表达语义色。
- 控件（按钮 / 输入 / 选择 / 文本编辑）保持 HTML/CSS 可维护，仅在轮廓、颜色、阴影、贴纸边缘上服从风格；不得把文字烤进不可伸缩图片按钮。

### G9 — 全状态覆盖与能力归位

目标：状态完整，且每项后端已支持的能力都在工作面里有明确归属，无不可达能力。

状态：空 / 已放入片源 / 方案展开 / 生成中 / 完成 / 失败，全部以世界对象表达。

能力归位：

- 术语 → 主屏方案中的术语开关 + 独立术语管理入口（术语对象，非数据表格）。
- 环境诊断 → 失败修复对象 + 高级诊断窗（非首屏常驻检查列表）。
- 任务历史 → 辅助入口，非完成态主视角。
- 任务详情 / 事件 → 运行中展开或子窗口。
- 结果审看 → 独立审看状态，使用字幕片 / 校对标记 / 质量修复对象，不退化为表格。
- 导出 → 完成态对象内的重新导出 / 打开文件 / 打开目录。

现状差距：见 §1 能力覆盖。多项能力当前不可达。

达成标准：

- 每项后端能力都能经由某个工作面对象到达；不存在「实现里有、界面里进不去」的能力。
- 完成态主视觉从片源转向输出；失败态只呈现与恢复相关的修复对象，不铺完整诊断面板。

### G10 — 性能与手感

目标：达到原生 App 的即时手感；不打包体积优化，但运行时要更顺。

现状差距：`App.tsx` 用 `lazy + Suspense` 且 fallback 是纯色 `WindowBootSurface`，存在首帧空白 / pop-in 风险；超大位图有解码 / 合成开销。

达成标准：

- 无首帧空白、无 FOUC、无懒加载分块可见闪烁；启动到可交互迅速。
- 交互与状态切换无可感卡顿、无布局抖动（layout shift）；过场短促、GPU 友好。
- 大资产不在运行时造成可感的解码 / 合成卡顿；必要时预解码 / 预载。
- 子窗口（配置 / 详细）打开迅速，无明显空窗期。

### G11 — 工程结构卫生

目标：仓库内只存在一棵活的前端实现树，构建干净、无死代码、无被禁视觉库绑架气质。

现状差距：见 §1 工程结构。

达成标准：

- 旧 Web 前端（router / layout / 旧 `*Page` / 仅旧路径使用的 components）从构建中移除，或按准则第 1 条「只证明后端对接可行」物理隔离出 `src` 编译范围。
- `lucide-react` 退出产品路径；如确需临时使用，标注为临时且不进入核心视觉。
- 全局样式裁剪到实际使用项，设计 token 单一来源。
- 拖拽收敛为当前桌面运行时的单一正确路径，删除死分支。
- `tsc --noEmit` 与 `npm run build` 均干净通过，无未引用模块滞留 `src`。

### G12 — 验证与验收纪律

目标：每个里程碑在真实桌面运行时窗口验证，按 web 感禁令清单与准则停止条件逐条自检。当前 Flutter spike 阶段以 Windows Flutter release 窗口为验收载体；若回到 Tauri 路线，则以真实 Tauri 桌面窗口为验收载体。

达成标准（每个里程碑）：

- 在真实桌面运行时窗口（主窗口 + 配置 / 工具子窗口）完成视觉与交互验证；Flutter spike 阶段不以 debug 结果替代 Windows release 文件夹运行，Tauri 路线不以 Vite 浏览器端口页面作为验收对象。
- 跑齐状态矩阵：六态 × 相关窗口，并在最坏内容集下验证布局（对应 G4）。
- 逐条过 §2「严禁：web 直觉泄漏」清单与准则 §11 停止条件，并签署。
- 关键状态留存截图归档至本目录或 `prototypes/`，便于回看对比。
- 验证结论按 `AGENTS.md` 如实说明：跑了什么、过了什么、未验证而存在风险的是什么。

## 4. 全局非妥协项

无论实现怎么走，下列任一被突破即判失败、回到设计判断：

- 看得出是网页 / 浏览器做的，或带任何 web 站点结构（路由、URL、页面跳转、纵向滚动文档、响应式回流）。
- 任务详情 / 设置 / 诊断 / 修复被做成主窗口内嵌网页 modal。
- 配置退化为 `overflow:auto` 的 provider 卡片滚动列表，或 provider 表格直铺。
- 世界退化为互不相干的母题拼盘，或一屏内新旧隐喻混搭。
- 失败被做成网页 hero / 错误页 / 展示海报，而非当前任务的状态 / 修复对象。
- 用纯色（无形状 / 文字冗余）承载关键状态，或用假百分比伪造进度。
- 用通用图标库 / 通用组件库决定产品气质。
- 为浏览器 / 窄屏 / 通用响应式牺牲主设计。

## 5. 验收总纲

整套前端最终须同时满足：

- 去掉产品名仍是一个固定的原生 App 工作面，不带任何 web 站点结构，看不出是浏览器技术做的。
- 单一连贯的设计世界（隐喻可探索），对象不是从功能目录 / 表格 / 面板推导。
- 配置承载于主从式偏好工具窗，详细层清晰分层，非配置台、非卡片滚动流。
- 布局在最坏内容下零碰撞、零意外裁切；主 CTA 是视觉主角。
- 设计系统真实可用：字重有效（打包真实字重字体）、中文不过小、token 单一来源。
- 状态可信、失败可懂、灰度可辨、每个控件状态可读。
- 资产风格与技术形态一致、alpha 合规、语义色不靠 hue-rotate；运行时无可感卡顿。
- 每项后端能力都有工作面归属，无不可达能力；仓库无死前端、无 `lucide` 绑架。
- 每个里程碑在真实桌面运行时窗口验证，并过 web 感禁令清单与停止条件。
