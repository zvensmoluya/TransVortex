# TransVortex 前端可实现设计规格

本文档是前端的**可实现设计规格**：把方向和标准（见 `FRONTEND_DEVELOPMENT_GOALS.md`）落成可照着开发的具体构图、行为、气质与设计系统值。

三层关系：

- 方向：`FRONTEND_POSITIVE_DESIGN_DIRECTION.md`、`FRONTEND_MAIN_SCREEN_STYLE_FRAME.md`（候选素材，可借用、可推翻）。
- 标准 / 验收：`FRONTEND_DEVELOPMENT_GOALS.md`（北极星 = 原生 App 感、反 web；web 感禁令清单；G1–G12）。
- **可实现规格：本文档**。

凡本文档与上述候选方向冲突，以本文档为准；凡与 Goal 的标准冲突，回到 Goal 重新对齐。

本规格覆盖**三个窗口的 MVP**：主窗口、翻译模型设置窗、语音识别设置窗。其余能力（术语维护、诊断、历史、任务详情、结果审看、导出复核）在 Goal G9 已要求归位，但属后续设计轮次，不在本规格内。

---

## 1. 主轴与世界原则

- 这是 Tauri 自绘的**原生客户端工作面**，不是网页。北极星与 web 感禁令以 Goal §0、§2 为准。
- **二次元只落在「世界对象 + 线条 + 配色」上，不落在布局容器上。** 布局永远是固定 App 工作面 + 扁平框定分区；不拿圆角装饰卡片承载界面。这是上一版失败的根因纠正。
- 圆角规则：允许用在**输入框、按钮、菜单、浮层、轻提示、片段/选中态**；**禁**把圆角卡片当布局容器或列表单位。

---

## 2. 产品结构总览

- **两个全局前置配置（配一次、不常动）**：翻译模型、语音识别。各自一个独立 Tauri 工具窗。
- **主窗口 = 一次任务**：放片源 → 三个运行设置 → 开始 → 看状态 → 取输出。翻译/ASR 在主窗口只以「配好没」的状态出现，点进去才配。
- 主窗口里**没有真正的配置**，只有「这次怎么跑 + 启动 + 结果」。

---

## 3. 已锁定的产品语义决策（含代码依据）

- **主窗口运行设置只有三个**（对过代码，均不含糊）：
  1. 输出格式（SRT / ASS / VTT，可多选）— `output.formats`
  2. 双语 — `output.bilingual`
  3. 术语生成（翻译时自动积累，开/关）— `allowSystemSuggestions`，驱动 `memoryBootstrapEnabled` + `memoryPatchEnabled`（[taskDraftAdapter.ts:58](desktop/src/adapters/taskDraftAdapter.ts#L58)）
- **「质量」砍出主窗口**：它是 `subtitleQualityMode`（off/conservative/balanced），本质是字幕整形力度的粗档（[subtitle_optimizer.py:254](src/transvortex/core/subtitle_optimizer.py#L254)）。主窗口默认走 `balanced`，未来若暴露归详细设置，并改用「字幕整形：轻/标准/关」这类说人话措辞。
- **输出目录砍出主窗口**：默认生成到**片源同目录**；目录不可写时由失败修复件给「选个文件夹」，不设常驻控件。
- **没有常驻「输出位」**：完成是**这一次任务的状态**，不另起区域、不铺海报。
- **主窗口「术语」开关语义要改**：现有 `toggleTerms`（[ClientHomePage.tsx:613](desktop/src/pages/ClientHomePage/ClientHomePage.tsx#L613)）切的是 `useProjectTerms`（使用术语/inject），**不是术语生成**。实现时驱动 `allowSystemSuggestions`，不要照抄旧逻辑。
- **使用术语 / 术语维护 / 预设术语表 另设计**，暂不进主窗口。耦合提醒：bootstrap/patch 负责「攒」、inject 负责「用」；设计「使用术语」时必须把「生成的术语回流到翻译」接上，否则主窗口「术语生成」单开会语义落空。

## 4. 主窗口规格

固定横向工作面，约 3:2（沿用 820×560 量级，最终值实现定）。左右重心：左片源、右控制面、底动作。不可缩放、不滚动、无路由。

### 4.1 分区

- **Z0 标题栏（顶部通栏，薄）**：自绘二次元标题栏，左=品牌+标题+一行轻状态字，右=最小化/关闭，`data-tauri-drag-region` 行为像原生。不放任何导航/标签。
- **Z1 片源位（左侧主角，画面最大视觉块，垂直居中偏上）**：
  - 空态：二次元「片源投递口」开着，中心「放入片源」，副「拖进来，或点击选择 · 视频 / 音频 / 字幕」。
  - 已选：投递口收着片源，显示**文件名**（主、大、优雅截断）+ **类型签**（视频/音频/字幕），已知则加语言方向小签。
  - 行为：整窗可拖入（Tauri 原生 `onDragDrop`），落点在此对象、drag-over 强反馈；点击→系统原生文件 dialog；右键→换片源/移除。
  - 边界：**不是路径输入框**；只显文件名+类型，完整路径走 hover tooltip 或右键。
- **Z2 运行设置（右侧竖向控制带，紧接 Z3 下方）**：三组常驻直接控件——输出格式（三切片多选）、双语开关、术语生成开关。改即生效，**无「保存」**。视觉是装置右脸的一排拨档/贴片，从属于片源。
  - 边界：不做成表单；不预留「更多设置」抽屉；**这条竖列不许变成 web 侧边栏/导航列**（靠间距、物件感、非等距排布做成「控制面」，不全高贯通，下方让位给 Z4）。
- **Z3 能力状态（右上角，两个小件）**：翻译、ASR 各一小状态件，显「已配好 / 需配置」+ 轻标识，点击→开对应配置窗；需配置时高亮并 gate 主动作。两个小件，不横贯成栏。
- **Z4 主动作 + 状态（底部偏中右，第二焦点）**：一个显眼主动作，其样子=当前状态，承载全部六态（见 §8）。失败/完成不另起区域。
- **Z5 角色位（可选，左下近片源）**：小型陪伴件，先静态或留空，预留空间，加入时不挤动布局。

### 4.2 动线与层级

片源（主）＞ 开始（焦点 CTA）＞ 运行设置（从属带）＞ 能力状态（右上，轻）。眼睛：片源 → 右控制面（看就绪、选怎么跑）→ 底部开始 → 右上状态确认。进 → 设 → 走，一条线，不回头。

## 5. 翻译模型设置窗规格

它是**模型配置**（成熟模型设置那套：供应商列 + 详情 + 默认模型）。独立工具窗，比主窗口大，横向容两栏。允许「稍微违规」地像原生模型设置面板（表单密度允许），但 ① 无圆角卡片容器 ② 原生工具窗非网页 modal ③ 表单气质不泄漏回主窗口。

字段只做现有的（`ProviderConfig`，[models.py:64](src/transvortex/app/models.py#L64)）。

### 5.1 分区

- **Z0 标题栏**：「翻译模型设置」，副「配好模型服务，选定默认模型」，右=关闭。
- **Z1 默认模型条（顶部，常驻结论）**：「翻译默认：<供应商 · 模型>　备用：<… / 无>」。未设时提示「还没选默认模型」。整窗唯一全局生效项，独立常驻。
- **Z2 供应商扁平列（左，窄）**：内置 OpenAI / Anthropic / Google Gemini / Google Vertex / …，+ 自定义。每行=名称 + 协议标 + 状态点 + 启用态；**选中=整行高亮（左强调边或底色），不是卡片**；行间靠分隔线/留白。底部「+ 添加供应商」（选协议格式 + base_url + key）。多供应商时此窄列可滚（侧列滚动，非卡片台）。
- **Z3 详情面板（右，宽，表单字段，分组靠小标题/分隔/留白，无卡片容器）**：
  - 协议格式 `api_type`：内置固定显示；自定义可选（openai 兼容 / anthropic / gemini / vertex…）。
  - Base URL：可改，内置带默认。
  - API key：password + 保存，**不回显**，存用户级 `auth.json`，**不进 YAML**（统一凭据方案）。
  - 模型：「拉取模型列表」→ 列表；勾选启用 / 指定「使用模型」。
  - 测试连接：一行可信反馈（成功/失败+原因），不堆报告块。
  - 高级（默认折叠）：`temperature`（现有，默认 0.1）；**自定义参数 / reasoning effort 留高级位，本轮不接**。
  - 「设为翻译默认」：写回 Z1 + 通知主窗口。
- **Z4 装置位（可选）**：翻译小机形象，先留位。

### 5.2 行为

缺 key → 标「缺 key」、详情突出 key、未配好不能设默认；保存/测试中 → working 轻反馈（非满屏 spinner）；连不上 → 标「连不上」+ 原因；设默认 → Z1 即时更新、该行标「默认」、发 `config-updated` → 主窗口右上「翻译」变「已配好」。

## 6. 语音识别设置窗规格

ASR 不是供应商列，是**选一个识别引擎**。独立工具窗，比翻译窗小。引擎映射对过代码（[asr.py:373](src/transvortex/core/asr.py#L373)）。

### 6.1 分区

- **Z0 标题栏**：「语音识别设置」，副「视频没有现成字幕时，用它把语音转成字幕」。
- **Z1 识别引擎（三选一 = 默认引擎，segmented，不是三张卡片）**：
  - **本机识别（faster-whisper）** — `local_inprocess` + `faster_whisper`。**默认、零 key。**
  - **FunASR（本地服务）** — `local_server` + `funasr_openai`，SenseVoice。可选、无 key、需先启动本地服务。
  - **云端识别（OpenAI Whisper）** — `remote` + `openai_transcriptions`，要 key。
  - 旁边一句「当前：本机」点明结论。
- **Z2 选中引擎参数（表单字段，分隔/小标题分组，无卡片容器）**：
  - 本机：模型规格 `model_size`（large-v3 / medium…）、运算设备 `device`（自动 / GPU / CPU）、就绪状态（模型是否就绪、GPU 是否可用，一行诊断）。无 key。
  - FunASR：Base URL（本地服务地址，如 `http://127.0.0.1:…`）、模型（SenseVoice，默认/可不暴露）、**无 key**；测试=服务是否可连接；提示「需先启动本地 FunASR 服务」。
  - 云端：协议（OpenAI 转写，固定）、Base URL（默认 api.openai.com）、模型（whisper-1）、API key（不回显，`auth.json`）、Endpoint（高级，一般不动）、测试。
- **Z3 装置位（可选）**：识别小机形象，先留位。

### 6.2 行为与任务时策略

- 默认 faster-whisper，零 key，丢个视频即可跑（就绪状态反映模型是否已下载/GPU 可用）。FunASR / 云端可选。配好任一 → 主窗口「ASR」变「已配好」。
- **任务时自动判断字幕来源**（默认不暴露）：丢字幕文件不转写、有内置字幕轨优先用、否则用配好的引擎转写。
- 强制旁路 / 指定字幕轨 = 高级，延后；ASR 失败由修复件给选项（换云端 / 选已有字幕）。
- 本轮**只做 FunASR 专属**，不暴露抽象的「通用本地 OpenAI server」。

## 7. 通知模型（系统原生）

把一部分状态从「窗内涂色」改为**系统原生通知**，更 App、更反 web，也让窗内不靠大块状态色喊话。

- **长任务跑完 / 失败，尤其窗口不在前台 → 发系统通知**（右下角 toast / 通知中心）：「字幕已生成 · 点击打开」「制作失败 · 点击查看」，点击聚焦 App。
- **窗口在前台**：任务安静落到完成态（系统通知可抑制）；失败在窗内以**修复件**给可操作动作。
- 窗内只保留极少、统一色调内的轻状态标识，颜色不当主要喊话手段。
- **实现待接**：当前 `capabilities` 只有 dialog/opener，**没有通知**。需加 `@tauri-apps/plugin-notification` + 权限。

## 9. 二次元气质

### 9.1 注册（register）

采用 **B：干净动画线稿 + 平涂（赛璐珞感）**——利落深色线、平涂色块、近白底、克制强调。二次元的识别度交给**线条和色块**承载，不交给装饰和柔焦。不走 A（柔软可爱手绘）那种易滑向「装饰糊、低对比、假层级」的方向。

### 9.2 配色（philosophy 锁定，实际 hex 上屏再校）

- 整体**明亮、柔和、统一的二次元浅色调**。**不是**深色高对比 IDE，也**不是**饱和霓虹/彩灯。
- 暖白底为主体（≥70% 画面）；柔墨字（深但不死黑，够读、不压抑——「对比」目标是可读，不是戏剧性）。
- **一个主色家族领调**（建议落在柔莓 / 柔珊瑚这类暖二次元色），其余颜色是它的低饱和邻近伙伴，**色调统一**，不是五个互不相干亮色并排。
- **强调克制**：主色只点焦点 CTA 和当前激活态，不铺面；一屏只有一个主强调焦点。
- **状态色大幅收回**：绿/黄/红只在统一色调内极少量用，重要成功/失败交给系统通知（§7）。
- 严禁：饱和霓虹、彩灯、等权重彩色堆叠、深色底、语法高亮配色。

### 9.3 材质 / 线条 / 图标

- 平涂 + 干净线稿；**线宽统一、圆头线帽、明确墨色描边**（非浑浊灰）。
- 轻投影表达层级；不做玻璃拟态 / 霓虹 / 满背景纹理。
- **禁环境装饰噪声**（散落星星、蕾丝、蝴蝶结当背景）；装饰只在承载含义处出现。
- 图标自绘小线性、统一线宽、同一画风；不让 `lucide` 决定气质。

### 9.4 角色 / 控件

- **角色**：小型陪伴件，画风同线稿，非大立绘；看板娘较难做，**先降级**（静态起步或留位）。
- **控件**：输入 / 按钮 / 选择保持 HTML/CSS，薄描边、允许小圆角（仅用于控件，非布局容器），focus/active 用主色；不烤进图片；长文本 / 路径不被装饰压住可读性。

## 10. 设计系统值（起点值，最终上屏微调）

### 10.1 字体与字重

- **打包一套带真实多档字重的字体**（Tauri 自带分发，打包体积不约束）。
- 只用三档真实字重：**Regular 400**（正文）、**Medium 500**（标签/小标题）、**Bold 700**（强调/CTA/品牌）。**禁用 950/930/880 这类渲染不出的精细字重。**

### 10.2 字阶（CJK 下限：正文 ≥12px，不出现 10/11px 承载有效信息）

| 用途 | 字号 | 字重 |
| --- | --- | --- |
| 片源文件名（主对象主文） | 20 | Bold |
| 主动作 CTA | 15–16 | Bold |
| 品牌 / 标题栏标题 | 13–14 | Bold |
| 区块小标题 | 13 | Medium |
| 控件标签 / 正文 | 12–13 | Regular/Medium |
| 次要 / 注脚（下限） | 12 | Regular |

### 10.3 圆角（仅控件 / 浮层，不用于布局分区）

- `r-sm` 6（切片/小控件）、`r-md` 10（按钮/输入）、`r-lg` 14（浮层/菜单）。布局分区一律不加圆角容器。

### 10.4 间距

- `4 / 8 / 12 / 16 / 24 / 32` 六档，统一取用。

### 10.5 颜色 token（命名 + 角色；hex 为起点，上屏校，警惕糖果/霓虹）

| token | 角色 | 起点 hex（待校） |
| --- | --- | --- |
| `--bg` | 暖白主体底 | #fff7f1 |
| `--surface` | 轻分区底（非卡片） | #fffdf8 |
| `--ink` | 柔墨字 | #2f2933 |
| `--muted` | 次要文字 | #7c7180 |
| `--line` | 分隔线 / 描边 | #eadde4 |
| `--accent` | 主色（柔莓/珊瑚，领调） | #ff6b9a |
| `--accent-soft` | 主色低饱和伙伴 | （由 accent 派生） |
| `--sky` | 次要交互 | #6fc7d9 |
| `--warn` | 注意 / 需配置 | #ffd166 |
| `--ok` | 成功（极少用） | #75c79a |
| `--danger` | 失败 | #e85d75 |

防糖果/霓虹的关键不在 hex 本身，而在**用量比例**（大面积中性 + 主色只点焦点 + 状态色收回）与上屏校色，以及色调统一。

## 11. 反 web / 反卡片 边界（验收钩子）

每个里程碑按 Goal §2「web 直觉泄漏」清单与 G12 逐条过，重点：

- 无路由 / URL / history / 纵向滚动文档 / 响应式回流。
- 三窗均**无圆角卡片容器**、无 `overflow:auto` 卡片台、无 provider 表格直铺、无网页 modal。
- 状态以「当前任务的态 + 系统通知」呈现，不铺色、不做错误页/海报。
- 在真实 Tauri 窗口验收，不以 Vite 浏览器页面为准；最坏内容下零碰撞、零意外裁切。
