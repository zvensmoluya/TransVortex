## 1. 产品结构

TransVortex 是固定工作面的 Windows 原生客户端，不是网页、后台管理台或多页面工作台。

当前用户可见窗口：

| 窗口 | 角色 | 主要职责 |
| --- | --- | --- |
| 主窗口 | 当前一次制作 | 选择片源、设置本单方案、运行、失败恢复和完成结果 |
| 应用设置 | 右侧扩展面 | 管理全局网络、应用下载的资源、存储及后续软件级设置 |
| 翻译模型设置 | 工具窗 | 管理翻译连接、模型、常用 routing 和全局网络方式 |
| 语音识别设置 | 工具窗 | 准备本机 Whisper、OpenAI Whisper 或 FunASR，并直接管理相关本机资源 |
| 任务处理 | 工作台 | 查找历史任务、查看事件、继续/取消、编辑和重新导出 |

诊断窗口保留给开发、测试和支持，不进入普通用户菜单。术语维护仍未形成完整产品表面。

## 2. 窗口模型

- 主窗口收起时为 `720 x 520`。左侧任务工作面始终固定为 `720 x 520`，无路由、无分栏和页面级滚动；打开应用设置不能使工作面回流、缩放或改变内容。
- 应用设置是同一个 HWND 内的 `480 x 520` 右侧扩展面。宽屏打开时只将原生窗口一次性扩到 `1200 x 520`，关闭时先收起面板内容，再一次性恢复到 `720 x 520`。两个工作面作为一个原生窗口整体移动、最小化和隐藏。
- 当当前显示器可用宽度不足 `1200` 时，原生窗口保持 `720 x 520`，应用设置改为窗口内右侧覆盖层。覆盖层只在打开期间拦截被覆盖区域的输入，关闭后不保留透明死区。
- 应用设置只承载全局网络、资源、存储和其他软件级设置，以紧凑的内容分类切换组织，不使用常驻导航栏，也不聚合翻译或语音识别页面。翻译模型设置与语音识别设置仍是独立工具窗；用户可以按自己的目的直接打开任一入口。
- 一项底层能力可以出现在多个合理上下文。例如全局网络既可在应用设置中编辑，也可在翻译模型设置中编辑；受管识别资源既可在应用设置中清理，也可在语音识别设置中直接管理。重复入口调用同一 Local Service 契约并自动同步状态，不要求 UI 跳转或用户手动刷新。
- 任务处理窗是可缩放、可最大化的工作台，同类单例并可定位目标任务。
- 普通工具窗和任务处理工作台按 `role:type` 记忆几何，并始终夹回当前显示器可见区域；应用设置不是独立窗口，不单独记忆几何。
- 子窗口不能各自拥有业务后端或权威任务状态。
- 文件和目录选择使用系统原生 dialog；核心流程不使用覆盖主窗口的全屏 modal。
- 关闭主窗口时收起全部产品窗口并驻留系统托盘；当前任务和 Local Service 继续运行。
- 恢复应用使用托盘图标或托盘菜单；真正退出只通过托盘“退出 TransVortex”，运行中必须先确认取消任务。

## 3. 主窗口

主窗口围绕一个片源就地变化：

```text
片源主体
  -> 本次识别 / 翻译 / 输出方案
  -> 当前唯一主动作
```

### 片源

- 支持拖入或系统文件对话框选择视频、音频和 SRT。
- 主视觉显示文件名和短位置提示，不铺完整路径。
- 视频自动检查内嵌字幕；界面不能暗示所有视频固定先做 ASR。
- ASS、WebVTT 和 LRC 当前只作为输出，不能伪装成可接受输入。

### 本次任务配置

- 使用自然语言和可点选择项表达源语言、目标语言、识别方案、翻译模型、单双语和输出格式。
- 选择常用翻译模型时写入完整 routing snapshot；临时直选模型不得暗中继承旧 fallback。
- 输出目录默认是片源同目录，只在目录不可写或重新导出恢复时让用户另选。
- “自动生成术语建议”只控制术语生成相关行为，不表示关闭已有人工术语的使用。
- 准备配置属于对应设置窗，本次任务选择属于主窗口，两者不能混成一个大表单。

### 六种状态

| 状态 | 主要信息 | 主动作 |
| --- | --- | --- |
| 空 | 新任务草稿和片源入口 | 选择片源 |
| 就绪 | 片源和本次方案 | 开始制作 |
| 受阻 | 缺少的翻译或识别准备 | 去对应设置 |
| 制作中 | 真实阶段、进度、分窗/分片和请求计数 | 取消任务 |
| 失败 | 一句话原因和具体恢复方向 | 重试、继续或去修复 |
| 完成 | 结果和仍需关注的质量提示 | 审看结果 |

完成态的“制作新片源”低于结果处理。失败态不把完整 doctor 报告作为默认入口。

## 4. 翻译模型设置

窗口采用连接列表与详情的主从结构，并区分两层概念：

- 连接：服务类型、名称、Base URL、凭据、连接测试，以及彼此分离的“上游可用模型”和“已启用模型”。打开已保存连接时自动尝试获取上游模型；刷新只是显式重试，不是正常使用前的必做步骤。上游结果不得自动写入连接，只有用户明确启用的模型才持久保存并进入后续 routing 选择；不支持列表接口或自动获取失败时保留手动模型 ID 入口。
- 常用模型：用户命名的 routing profile，包含主模型、有序 fallback，以及每条 route 的默认推理强度。

窗口顶部使用“连接 / 常用模型 / 网络”三个稳定页签。网络页签是全局设置，只公开跟随系统、直连和本地代理；本地代理固定 `127.0.0.1`，只输入 HTTP / Mixed 端口。同一设置也出现在应用设置的“网络”分类，两处复用同一表单语义和保存逻辑。它不进入单个连接详情，也不与 Base URL 合并成一个字段。

保存连接不改变当前 routing；修改常用模型不隐式改写连接。API key 保存到用户级凭据文件，不回显，不进入 Provider YAML。

上游模型发现是设置窗口会话内的辅助目录。失败、空结果或上游移除模型都不得清空已启用模型；已被 routing 引用的模型仍需先解除引用才能停用。大模型目录需要筛选并限制一次渲染数量，避免把全部发现结果直接堆进连接配置。

普通设置不公开 endpoint mapping、credential_id、连接池等协议内部字段。模型容量覆盖留在连接的模型高级区域；思考程度默认值属于常用模型，并作为主模型或备用模型行内的紧凑入口。主窗口不把模型与思考程度拆成一句配置语法，而是在翻译模型菜单内提供同一入口，用于当前任务临时切换。选择浮层必须先表达互斥的“自动 / 手动”策略，只有手动策略被选择后才以动画展开离散滑杆；自动状态只显示解析出的当前档位，不得同时渲染活跃滑杆。`service_default` 在高级区域显示为“由模型服务决定”，并与支持模型的“关闭”明确区分。滑杆采用离散吸附、档位文字过渡和克制的滑块反馈，同时遵循系统减少动态效果设置。连接页只为当前选中模型保留“测试请求”档位，用于真实连接测试且不持久化为运行默认。

## 5. 语音识别设置

三个方案独立选择，不自动回退：

- 本机 Whisper：运行组件始终受管；模型可由应用自动准备，也可验证并原地使用已有的兼容模型目录；NVIDIA 组件按运算方式选用。
- FunASR：连接用户提供的本地服务并做最小音频测试。
- OpenAI Whisper：使用官方 Transcriptions 地址和独立凭据。

本机 Whisper 的首次设置是一次完整产品动作，不是组件管理器：用户选择“应用下载 / 使用已有模型”、模型和运算方式后，主动作顺序完成缺失资源与方案保存。静态配置、活动任务和终态恢复不能同时平铺；活动任务出现后，它替换配置主体并显示“运行组件 / 模型 / 校验并启用”三个稳定阶段。完成回到当前方案摘要；取消和失败保留原因、续传说明与恢复动作。当前使用与尚未应用的草稿必须使用不同文案表达。

已有模型入口使用“查找模型”而不是要求用户判断某个文件。目录选择器允许选择模型目录或其上层目录；单个候选自动带回，多个候选用模型标签、相对位置和大小组成选择列表。候选发现与兼容性测试必须分成两个状态：发现阶段只检查可识别的目录结构，启用前由受管运行组件完成真实加载和最小转录。外部模型文案只表达“兼容”或“自定义”，不得把配置相似度解释为官方来源、模型真伪或识别质量。

下载计划必须把“识别资源位置”作为普通用户概念显示在运行组件和模型旁边，而不是暴露 `app_data_root` 等实现字段。首次下载前允许选择另一个本地专用文件夹，并显示目标盘可用空间；空间不足时主动作不可执行，但更改位置入口保持可用。UI 的空间值用于提前解释，Local Service 在开工前执行权威复核。已有资源、下载断点或活动任务时不得直接改写路径；首版明确说明不会自动搬动大文件，后续迁移必须具备独立进度、逐文件校验、取消和失败回滚。

用户可以从语音识别设置直接打开资源管理，也可以从应用设置处理同一批受管资源。只列出并删除 TransVortex 下载到受管目录的运行组件、模型和加速组件；外部模型始终原地保留且不进入删除列表。删除前说明对当前识别方案的影响，删除当前运行组件或模型后允许方案变为未就绪，后续使用时再重新下载或改选。

界面只根据后端 `readiness.can_run` 判断能否执行，不根据“是否需要 key”自行推断。下载、取消、续传和组件校验必须显示真实状态。首轮 CPU-only 发布不展示 NVIDIA 安装动作；以后明确选择 NVIDIA 时仍不得静默降级 CPU。

## 6. 任务处理窗

任务处理窗使用任务片列 + 当前任务工作区：

- 按状态筛选，并按片源、任务编号、状态或失败摘要搜索。
- 查看创建/更新时间、运行记录、可用操作和分页事件。
- 对可恢复任务执行继续，对运行中任务执行取消。
- 对已完成任务审看和编辑字幕译文及开始 / 结束时间，按上一条 / 下一条问题连续校对；时间码可直接输入或按 0.1 秒微调，片段内校验通过后保存结构化字幕，再按格式、单双语、双语顺序和换行偏好重新导出。
- 保存、待导出、导出中、已交付和导出失败是稳定可见的交付状态；失败不替换整个编辑工作区。
- 只有在需要时显示任务目录、结果目录和目录可写性检查。

窗口内部切换任务，不为详情、历史或结果再次生成新窗口。

## 7. 视觉与反馈

主视觉语言是安静的个人字幕制作工作间：暖白工作面、草莓粉焦点、墨线和局部赛璐珞物件。具体对象、颜色和动画见视觉交互规范。

- 动画只解释状态变化，不能使左侧固定工作面回流。打开和关闭应用设置各只调整一次原生 bounds，面板外壳立即稳定，仅内容使用短距离位移和透明度过渡，不逐帧拉伸 HWND；分类切换与代理字段展开保持在固定内容区内，并遵循系统“减少动态效果”设置。
- 状态由形状和文字表达，颜色只强化。
- 核心图形与品牌资产使用统一画风，不让通用组件库决定产品气质。
- 设置和编辑器允许工具密度，不能为了风格牺牲扫描和输入效率。

## 8. 禁止模式

- 常驻左栏、顶栏导航、Dashboard、卡片墙和卡片套卡片。
- 用默认 Material、通用图标库、圆角和阴影替代设计判断。
- 主窗口路由、网页式详情页、响应式断点回流或大块滚动页面。
- 把任务详情、翻译连接、识别方案、诊断和失败修复都聚合进应用设置，或在扩展时拉伸、重排左侧任务工作面。
- 用假进度、轮播历史日志或装饰文案制造工作感。
- 直接展示原始错误、语言码、完整任务 id 或本地路径作为主要文案。

出现这些模式时应停止实现，先修正产品结构，而不是继续调色。

## 9. 验收

前端改动至少按风险选择：

- `flutter analyze`
- `flutter test`
- 影响主流程时运行 `flutter build windows`
- 使用 release smoke 覆盖相应状态或窗口
- 在真实 Windows release 窗口检查最长名称、缺配置、失败和工作中状态

自动截图和 smoke 证明接线与布局回归，不替代用户手动选择片源、提交、观察运行、完成和审看结果的完整验收。具体命令见 [`../../运行与测试指南.md`](../../运行与测试指南.md)。
