# TransVortex 首屏风格设计稿

本文档描述第一张需要验证的具体首屏风格稿。

它仍然不是最终 UI 规格，也不要求立刻接通后端。它用于指导第一轮静态原型、图片生成和视觉验证。

## 1. 当前目标

先验证一个问题：

> 二次元少女可爱手绘风的个人译制小屋，能不能承载“片源进、字幕包出”的主体验，同时不退回后台、剪辑软件或配置台。

第一轮只做首屏和少量状态，不做完整前端。

必须覆盖：

- 空状态。
- 已放入片源。
- 制作便签展开。
- 生成中。
- 完成。
- 一个失败状态。

## 2. 风格定位

### 选择

采用：

> 二次元少女可爱手绘风 + 个人译制小屋物件 UI。

画面像一个明亮、干净、有一点同人译制气质的小工作桌。

界面里的主要东西不是导航栏、面板和表格，而是：

- 一个片源投递盒。
- 一张制作便签。
- 几台小型译制设备。
- 一个字幕交付包。
- 一个少女助手。

### 不采用

不走这些方向：

- 专业字幕软件。
- 视频剪辑软件。
- SaaS dashboard。
- 黑色赛博控制台。
- 手游大厅。
- 儿童网页。
- 纯看板娘皮肤。
- 全控件图片化的游戏 UI。

## 3. 首屏构图

首屏使用单画面工作桌结构。

不使用常驻左侧导航、顶部导航、页面标签栏、统计块或卡片网格。

推荐构图：

```text
┌────────────────────────────────────────────┐
│                                            │
│  [少女助手小插画]      [制作便签]           │
│                                            │
│        [片源投递盒 / 片源包]                │
│                                            │
│              [开始译制]                     │
│                                            │
│  [轻状态文字]              [交付包]         │
│                                            │
└────────────────────────────────────────────┘
```

布局重点：

- 片源投递盒是最大对象，位于视觉中心。
- 制作便签在右上或右侧，不抢主对象。
- 交付包在右下或底部，是输出预期。
- 少女助手可以在左上或左侧，但不能遮挡主操作。
- 主按钮靠近片源投递盒和交付包之间，表达“开始制作”。

## 4. 核心视觉对象

### 少女助手

用途：

- 空状态欢迎。
- 处理中陪伴。
- 完成状态提示。
- 失败状态解释。

不要把她做成：

- 常驻聊天机器人。
- 导航菜单。
- 每个按钮旁边都出现的装饰。
- 遮挡主要信息的大立绘。

建议形象：

- 年轻、轻快、亲切。
- 像个人译制小屋的助手。
- 服装可以有围裙、短外套、耳机、发夹、贴纸等轻量元素。
- 不需要强职业制服。
- 不需要科幻、魔法、舰桥、夜空元素。

首屏空状态中，少女助手可以拿着字幕纸条或片源封套，视线引向片源投递盒。

### 片源投递盒

首屏主对象。

空状态：

- 像一个打开的软边文件盒、投递托盘或片源篮。
- 里面有几条淡淡的字幕纸带。
- 中央文案：`放入视频或字幕文件`。

已放入片源：

- 投递盒里出现一个片源封套。
- 封套上显示文件名和类型。
- 可以有小标签显示 `视频`、`字幕`、`日语`、`简体中文`。

不要做成普通文件路径输入框。

### 制作便签

表示当前任务方案。

正面内容：

```text
当前制作单
日语 -> 简体中文
源字幕：自动
翻译：日常字幕方案
术语：项目词库
输出：SRT + ASS
```

视觉：

- 像贴在桌面上的便签或轻量委托单。
- 可以有手绘胶带、夹子、小标签。
- 不要做成通用设置面板。

点击后展开。

展开方式：

- 像便签翻开或展开一页。
- 第一层只显示高频项。
- 高级设置入口放在底部或角落。

### 识别小机

出现在制作便签展开层。

表示源字幕获取方式。

高频选项：

- 自动。
- 使用内置字幕轨。
- 本地 ASR。
- 远端 ASR。
- 不识别，只处理已有字幕。

视觉：

- 像一台小型转写机、录音机或字幕取出器。
- 只在配置展开、失败修复或首次配置中出现。

### 翻译小机

出现在制作便签展开层。

表示翻译模型 API。

高频内容：

- 当前翻译方案。
- 当前模型。
- 是否可用。
- 换模型。
- 测试连接。

视觉：

- 像一台小型译写机或带纸带出口的小设备。
- 可以吐出一条翻译字幕纸带。
- 不要做成 provider 表格。

### 交付包

表示输出。

空状态：

```text
交付包
等待生成
SRT / ASS
```

完成状态：

```text
字幕已生成
SRT    打开
ASS    打开
检查字幕
```

视觉：

- 像一个整理好的小文件包、信封、压缩包或字幕交付盒。
- 输出文件可以像包里的小标签。

### 修理贴

失败时出现。

示例：

```text
翻译模型无法连接
当前制作单使用 Claude Haiku，但凭据不可用。

[保存 API key] [换一个模型] [查看细节]
```

视觉：

- 像醒目的修理便签或红粉色提醒贴。
- 可以由少女助手指向问题。
- 只解释当前阻塞点。
- 不展示完整诊断面板。

## 5. 状态设计

### 空状态

主文案：

```text
放入视频或字幕文件
```

辅助信息：

```text
当前制作单会自动处理源字幕、翻译和交付格式。
```

显示：

- 少女助手。
- 片源投递盒。
- 制作便签摘要。
- 空交付包。
- 主按钮禁用或弱化。

### 已放入片源

显示：

- 片源封套。
- 文件名。
- 语言方向。
- 输出预期。
- 可用的开始按钮。

不要自动展开所有配置。

### 制作便签展开

显示：

- 语言选择。
- 源字幕获取。
- 翻译方案。
- 术语开关。
- 输出格式。

高级入口：

```text
详细设置
```

详细设置里才出现 API key、provider、ASR 地址、模型列表、连接测试等。

### 生成中

主状态：

```text
正在生成字幕
```

短解释：

```text
正在获取源字幕，之后会自动翻译并整理交付包。
```

允许：

- 轻动画。
- 少女助手处理中表情。
- 片源投递盒到交付包之间出现短纸带或进度痕迹。
- `查看事件` 作为展开入口。

不要：

- 把后端阶段铺成常驻流水线。
- 显示 dashboard 指标墙。

### 完成

主状态：

```text
字幕已生成
```

焦点转到交付包。

显示：

- 输出文件。
- 打开文件。
- 检查字幕。
- 重新导出。

### 失败

只显示和恢复相关的修理贴。

示例：

```text
无法获取源字幕
本地 ASR 没有启动，也没有检测到内置字幕轨。

[改用远端 ASR] [选择已有字幕文件] [查看诊断]
```

不要在失败首屏展示完整环境检查列表。

## 6. 色彩与材质

### 基础色

方向：

- 暖白底。
- 莓粉主强调。
- 汽水蓝辅助。
- 布丁黄提醒。
- 深紫灰文字。

示例：

```css
--bg: #fff7f1;
--surface: #fffdf8;
--ink: #2f2933;
--muted: #7c7180;
--line: #eadde4;

--accent: #ff6b9a;
--accent-2: #6fc7d9;
--accent-3: #ffd166;
--ok: #75c79a;
--danger: #e85d75;
```

### 材质

使用：

- 纸片。
- 贴纸。
- 封套。
- 软塑料小设备。
- 字幕纸带。
- 轻手绘描边。

避免：

- 玻璃拟态。
- 深色霓虹。
- 金属 HUD。
- 大面积渐变。
- 复杂纹理铺满背景。

## 7. 控件原则

插画负责世界感，控件负责可用性。

按钮、输入框、选择器、文本编辑器不要全部图片化。

允许：

- 软描边。
- 轻贴纸边缘。
- 少量小装饰。
- 明确 hover / focus / disabled 状态。

不允许：

- 文字嵌在不可伸缩图片按钮里。
- 每个控件都用独立图片背景。
- 长文本和路径因为装饰而难读。
- 字幕编辑区变得不适合编辑。

## 8. 第一轮素材清单

如果使用 imagegen 或其他生图流程，第一轮只需要这些资产：

- 空状态少女助手。
- 片源投递盒。
- 已放入片源封套。
- 制作便签。
- 翻译小机。
- 识别小机。
- 交付包。
- 修理贴。

每个资产优先生成透明背景 PNG，便于前端组合。

暂不生成：

- 大量按钮背景。
- 完整房间大背景。
- 多个复杂角色姿势。
- 所有配置项图标。

## 9. 第一轮验收问题

看到静态首屏后，必须能回答：

- 第一眼是否知道要放入视频或字幕文件？
- 是否知道当前会生成字幕交付包？
- 是否没有像后台、剪辑软件、配置台？
- 少女助手是否帮助理解，而不是抢主操作？
- 制作便签是否能承载配置摘要？
- 完成和失败状态是否有明确动作？

如果这些问题回答不了，不进入工程实现。
