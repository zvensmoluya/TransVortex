# TransVortex 前端正向设计方向

本文档补足 `rules/FRONTEND_FAILURE_RECOVERY_RULES.md` 没有说明的正向设计方向。

它不是最终设计稿，也不是实现教程。它记录当前候选方向，用于回答：

- TransVortex 前端应该往什么视觉和交互方向走。
- 复杂配置如何进入界面而不变成配置台。
- 哪些设计判断可以作为后续原型和实现的验收依据。

更具体的首屏构图和风格稿见 `FRONTEND_MAIN_SCREEN_STYLE_FRAME.md`。如果风格稿验证失败，应回到本文档调整候选方向，而不是直接进入实现。

## 1. 设计命题

TransVortex 前端不是后台、控制台、剪辑软件或专业字幕软件。

当前候选命题是：

> TransVortex 是一个二次元少女可爱手绘风的个人译制小屋：用户把片源交进来，贴上制作便签，收取字幕交付包。

这个方向允许明显的风格化和一定程度的“水土不服”，但不能牺牲基础可用性。

用户必须能直接理解：

- 放入视频或字幕文件。
- 确认语言和译制方案。
- 开始生成字幕。
- 检查或打开输出文件。
- 出错时知道修什么。

## 2. 为什么选择这个方向

TransVortex 的真实使用场景偏小众字幕需求，尤其是日漫、ASMR、同人向片源和个人译制场景。

如果沿着“专业工具”设计，很容易变成：

- 视频剪辑软件。
- 字幕编辑器。
- SaaS dashboard。
- provider 配置后台。
- 开发调试工作台。

这些方向都与失败恢复规则冲突。

二次元少女可爱手绘风不是为了装饰，而是为了建立一套能约束布局、颜色、对象和状态的设计语言。它要帮助前端摆脱“页面 + 面板 + 表格 + badge”的默认形态。

## 3. 核心对象

界面不从后端步骤推导，而从用户能理解的对象推导。

### 片源包

代表输入的视频、音频、字幕文件。

它是首屏主对象。空状态时表现为“等待投递片源”；用户选择文件后表现为一个已放入的小包、封套或素材盒。

片源包只展示必要信息：

- 文件名。
- 类型。
- 源语言。
- 目标语言。
- 是否检测到内置字幕。

### 制作单

代表当前译制方案。

它不是配置表，而是一张贴在片源旁边的制作便签。正面只显示高频摘要：

- 源语言到目标语言。
- 源字幕获取方式。
- 翻译模型或方案名。
- 术语记忆是否参与。
- 输出格式。

点击制作单可以展开编辑。展开层允许修改高频项，并继续进入详细设置。

### 识别小机

代表源字幕获取能力，也就是 ASR 或内置字幕轨选择。

它不作为首屏常驻大页面。只有在制作单展开、首次配置、失败恢复、或用户主动切换源字幕方式时出现。

### 翻译小机

代表翻译模型 API 和路由。

它不直接表现为 provider 表格。普通用户看到的是当前翻译方案；高级用户可以进入详细设置修改 provider、base_url、model、API key、fallback 和连接测试。

### 术语卡

代表术语记忆、角色称谓、固定译名和作品词库。

术语卡默认不抢主流程。它在制作单中以“使用项目词库 / 不使用 / 严格术语”这类可理解状态出现。详细术语管理可以独立进入。

### 交付包

代表输出字幕文件。

完成后重点展示交付包，而不是任务历史或后台列表。交付包包含：

- SRT。
- ASS。
- VTT。
- 任务目录。
- 检查字幕入口。
- 重新导出入口。

### 修理贴

代表错误、阻塞项和恢复动作。

失败时不展示完整诊断面板。只出现当前需要处理的修理贴，例如：

- 翻译 API key 不可用。
- 本地 ASR 没启动。
- 没有检测到源字幕。
- 输出目录不可写。

每张修理贴必须给出明确动作。

## 4. 首屏结构

首屏不使用常驻左侧导航、顶部导航、卡片网格或 dashboard。

首屏应围绕一个句子组织：

> 把这个片源，按当前制作单，生成字幕交付包。

最小首屏对象：

- 片源包入口。
- 制作单摘要。
- 交付包预期。
- 主动作按钮。

示意：

```text
[片源包入口]
  放入视频或字幕文件

[制作单]
  日语 -> 简体中文
  源字幕：自动
  翻译：日常字幕方案
  术语：项目词库
  输出：SRT + ASS

[开始译制]

[交付包]
  等待生成
```

这只是结构示意，不代表最终布局必须上下排列。

## 5. 配置进入方式

配置可能是高频能力，但不能成为首屏骨架。

普通用户默认只看到制作单摘要。复杂配置通过三层进入：

1. 制作单正面：高频摘要。
2. 制作单展开层：常用切换。
3. 详细设置：API、ASR、本地服务、高级运行参数。

### 高频配置

这些可以在制作单展开层中出现：

- 翻译方案。
- 翻译模型。
- 源字幕获取方式。
- 本地 ASR / 远端 ASR。
- 输出格式。
- 双语字幕。
- 术语记忆是否参与。

### 详细配置

这些不应默认出现在主屏：

- provider endpoint。
- request mapping。
- response mapping。
- routing fallback 细节。
- ASR chunking。
- 静音检测。
- 并发、超时、重试。
- 字幕 CPS 阈值。
- ASS 具体字体、描边、边距。
- memory bootstrap / inject / patch / merge 细项。

详细配置可以存在，但要明显是高级层。

## 6. 运行状态

任务步骤是内部实现，不是主界面分区。

正常运行时，界面只需要表达：

- 正在生成字幕。
- 当前正在做什么的短句。
- 可以展开查看事件。

不要把后端流水线做成常驻结构骨架。

允许在展开细节、失败恢复、任务详情中显示阶段信息。

## 7. 结果体验

完成后，主视觉应从片源包转向交付包。

优先展示：

- 输出文件。
- 打开文件。
- 打开任务目录。
- 检查字幕。
- 重新导出。

任务历史是辅助入口，不是完成状态的主视角。

字幕检查可以进入独立审看状态。审看状态可以使用字幕片、校对标记、术语卡、质量修理贴等对象，但不应退化成数据表格。

## 8. 视觉语言

### 总体风格

采用二次元少女可爱手绘方向，但控制为“个人译制小屋”，不是儿童玩具、手游大厅或动漫皮肤后台。

关键词：

- 轻快。
- 个人化。
- 小众译制。
- 少女助手。
- 手绘物件。
- 纸片、贴纸、封套、包裹、小设备、字幕片。
- 清楚、稳定、可操作。

### 图片资产使用原则

图片和插画用于核心世界对象，不用于所有控件。

适合使用插画或生成图片的对象：

- 少女助手。
- 空状态片源入口。
- 片源包。
- 制作单。
- 识别小机。
- 翻译小机。
- 交付包。
- 修理贴。
- 完成状态。
- 失败状态。

不建议图片化的对象：

- 普通按钮。
- 输入框。
- 下拉选择。
- 长文本编辑。
- 字幕正文编辑。
- 可复制的文件路径。

按钮、输入框和编辑器应保持 HTML/CSS 可维护性，只在轮廓、颜色、阴影、贴纸边缘或小装饰上服从整体风格。

### 色彩方向

允许使用可爱、明亮、二次元的配色，但必须控制比例。

建议基础：

- 大面积暖白或柔和浅色底。
- 深紫灰或墨色文字。
- 莓粉作为主强调。
- 汽水蓝作为辅助强调。
- 布丁黄作为提醒色。
- 低饱和绿色只作为成功状态，不作为主色。

避免：

- 深蓝黑赛博。
- 大面积紫蓝渐变。
- 冷灰绿森林感。
- beige 手帐风。
- 纯黑 HUD。
- 霓虹星空。

示例色值只作为起点，且**已被 `FRONTEND_DESIGN_SPEC.md` §10.5 取代**——实现以 SPEC 的 token 表为准（主色家族锁定草莓/樱花粉、明亮克制赛璐珞、状态色降为罕用语义色）。下面这组旧值不要再直接采用：

```css
--bg: #fff7f1;
--surface: #fffdf8;
--ink: #2f2933;
--muted: #7c7180;
--line: #eadde4;

--accent: #ff6b9a;
--accent-2: #6fc7d9;
--accent-3: #ffd166;
--ok: #75c79a;
--danger: #e85d75;
```

## 9. 文案语气

中文文案可以亲切，但不能过度卖萌。

推荐：

- 放入视频或字幕文件。
- 开始译制。
- 当前制作单。
- 源字幕获取。
- 翻译方案。
- 交付包。
- 需要处理。

谨慎使用：

- 过度拟人化。
- 大量语气词。
- 看板娘式对话。
- 让用户猜测含义的世界观词。

如果使用世界观词，必须在同一处保留清楚解释。

例如：

```text
翻译小机
连接当前翻译模型 API
```

## 10. MVP 原型范围

第一阶段不要重建完整前端。

先做一个不依赖完整后端的主屏假数据原型，验证：

- 空片源状态。
- 已选择片源状态。
- 制作单展开。
- 生成中状态。
- 完成状态。
- 一个失败修理贴。

这个原型允许使用假数据和假动作。

通过主屏方向后，再接最小后端能力：

- 选择文件。
- 读取配置摘要。
- 启动任务。
- 显示任务状态。
- 展示输出文件。

## 11. 正向验收

一个设计方案至少应满足：

- 第一眼能看出这是“片源进、字幕包出”的工具。
- 不依赖左侧导航、顶部导航、表格、卡片墙表达主要功能。
- 配置以制作单和展开层承载，而不是作为首屏主体。
- ASR、翻译模型、术语记忆是方案能力，不是并列后台模块。
- 任务步骤只作为状态解释、失败恢复或展开细节出现。
- 插画和视觉资产服务于核心对象，不替代基础控件。
- 二次元少女可爱风服务于小众译制场景，不让用户失去操作确定性。

如果一个方案去掉 TransVortex 名字后仍像后台、SaaS、普通设置页、剪辑软件或开发工作台，应停止并重做结构。
