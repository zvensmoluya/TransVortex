# Flutter 视觉、动效与 CG 场景规范

本文档决定 TransVortex 如何通过世界对象、线条、材质、角色、粒子、Shader 和场景级演出表现为具有高辨识度的二次元原生客户端。

它不把某组色值当作设计起点。颜色服务于对象关系、注意力和可读性；实际色值允许根据真实 Windows Release 上屏效果调整。`tokens.dart` 是当前实现快照，不是审美边界。

## 1. 视觉气质

TransVortex 是一个把专业字幕工作面与高张力视觉演出结合的个人译制工作间。它的审美目标不是“避免像游戏”或“保持克制”，而是在每个有价值的时刻展示足够大胆、有记忆点且技术上出众的表现力。

- 可交互工作面要支持长时间使用；启动、导入、状态跨越、完成、失败恢复和退出等关键时刻可以暂时接管整个窗口。
- 可爱感和世界观可以进入物件形态、完整插画、角色、景深、粒子、视差、音效与 2D / 2.5D CG 演出，不限于局部装饰。
- 鼓励大胆运用全屏转场、Shader、粒子、动态材质、角色演出和奇观化状态变化；现有视觉对象是起点，不是可用表现手段的上限。
- 表单和编辑器仍要高效可扫描，但这不禁止在其上、其后或场景切换期间建立高完成度视觉层。

## 2. 世界对象

| 对象 | 产品含义 | 常见位置 |
| --- | --- | --- |
| 封套 / 投递口 | 片源、当前任务 | 主窗口 |
| 字幕纸带 | 正在制作的内容、产出结果 | 主窗口、结果编辑 |
| 纸签 | 模型、语言、格式等短信息 | picker、设置窗 |
| 胶带 / 夹子 | 选中、固定、默认关系 | 连接列表、常用模型 |
| 线缆 / 信号点 | 服务连接和测试过程 | 翻译、识别设置 |
| 印章 | 保存成功、制作完成 | 主动作、完成态 |
| 修理便签 | 失败原因和恢复动作 | 主窗口、任务处理 |

这些对象是当前已成立的视觉词汇，不是白名单。它们可以是局部轮廓，也可以扩展为完整插画、角色表演或全窗口场景；新的材质、隐喻和特效只要与当前产品时刻形成清楚关系，就可以进入设计。

## 3. 颜色原则

- 常驻工作面可以使用低彩度留出注意力，也可以因场景方向重新建立色彩系统；它不是不可更改的审美前提。
- 草莓粉是当前品牌锚点而不是色域边界。火焰、冷光、震荡、空间扭曲等场景可以建立自己的完整色彩和发光关系。
- 特效用色可以主动建立氛围、视线和记忆点，不要求每种颜色都必须对应一个功能字段。
- 成功、失败和注意的关键含义不得只依赖颜色；颜色、发光、材质和动效仍可以承担主要视觉表现。
- 同一窗口上屏协调优先于跨窗口机械复用同一个色值。
- 调色必须通过真实 Release 截图判断，不以 token 数量、色相数量或设计表格完整度作为完成标准。

## 4. 反馈节奏

| 交互 | 反馈 | 建议时长 |
| --- | --- | --- |
| hover | 物件或纸签轻抬、墨线加深、局部提亮 | 90-140ms |
| press | 原位下压或轻微缩放，不改变布局尺寸 | 70-110ms |
| 选择 | 胶带边、夹子或纸签位置变化；文字保持可读 | 140-220ms |
| 异步工作 | 当前动作进入可持续、有层次且与真实阶段同步的运动 | 持续到结束 |
| 成功 | 盖章、纸带交付、角色反应或场景级完成演出 | 220-1200ms |
| 失败 | 修理便签或断开的信号出现，直接连接恢复动作 | 160-260ms |
| 场景转场 | 可暂时接管整个 UI，使用燃烧、溶解、碎裂、漩涡、空间折叠或角色演出 | 450-1800ms |

动画既可以解释状态，也可以承担品牌表演、情绪和纯粹的视觉奇观。可交互阶段的固定格式控件不应因 hover、loading、长文案或图标出现而意外推动布局；显式的场景转场期间则允许整个 UI 变形、燃烧、碎裂、离场或重组。

## 5. 场景级动效

- 允许启动、退出、任务开始、阶段跨越、完成、失败恢复、窗口切换和重要交付操作使用全窗口演出。
- 鼓励组合 `CustomPainter`、Fragment Shader、粒子、矢量或骨骼动画、序列帧、透明视频、音效和 Windows 原生窗口合成能力，不为了保持单一技术栈而降低效果上限。
- 场景演出可以暂时隐藏、替换或捕获当前 UI，但必须有明确的进入、结束、取消或超时路径，不得把窗口留在无法交互的中间帧。
- 系统“减少动态效果”开启时提供空间位移更少、时间更短或静态终态的替代演出；这是同一设计的可访问版本，不是取消主版本表现力的理由。
- 场景的动画可以比业务数据更丰富，但不得伪造任务进度、成功、失败、保存或交付结果。

## 6. 应用图标

- 当前图标沿用主窗口的胶片封套、字幕纸带和胶带对象，不使用默认 Flutter 标记或临时文字缩写作为发布资产。未来可以随品牌方向引入角色或重做图标隐喻。
- 大尺寸母版位于 `desktop_flutter/assets/branding/app_icon.svg`；`256px` 保留胶片孔和完整纸带细节。
- 小尺寸母版位于 `desktop_flutter/assets/branding/app_icon_small.svg`；`48px`、`32px` 和 `16px` 去掉胶片孔，只保留封套折线、粉色字幕条和青色角标。
- `scripts/build_brand_assets.ps1` 生成 PNG 母版以及供窗口、任务栏、托盘和 NSIS 共用的多尺寸 ICO。生成后必须验证 `256/48/32/16` 四档都存在。

## 7. 主窗口

- 空态是打开的投递口；拖入时盖口和落点共同响应。物件下方保留新任务设置和明确的“选择片源”主动作，不能把文件选择能力藏进整块隐形点击区。
- 就绪态是收好的片源封套，任务配置仍在物件下方完成。
- 制作中不是通用 spinner：封套应表现出字幕纸带正在被处理。纸带使用九个稳定分段表达检查、读取、识别、术语、分片、翻译、对齐、质量和写出，已完成段、当前段内进度和后续段在静止截图中也应可区分；移动信号点只强化真实总体进度。
- 纸带下方使用稳定的阶段标题、分窗/分片计数和累计模型请求，短时动作只补充当前发生的批量补回、自动拆分或格式修复。不能轮播历史事件、原始日志或纯装饰文案制造“正在工作”的假象。
- 完成态让字幕纸带成为交付件，可以使用全窗口交付、纸带展开、章印、角色或 CG 演出；仍有质量或交付提醒时，演出和结束画面都不得把结果伪装成完全通过。
- 失败态可以使用修理贴、卡住的纸带、信号断裂或全窗口场景变化。无论风格多强，结束后都必须留下可信原因和直接恢复动作。

## 8. 设置窗

设置窗保留高效表单骨架，但视觉风格和动效可以进入整个窗口，包括：

- 连接、模型、网络方式和引擎的选择行。
- 字段分组标题、默认关系和选中边缘。
- 保存、测试连接、自动发现模型、显式刷新和失败恢复的反馈。
- 菜单、picker、轻量提示和空状态。

不得为了风格把 Base URL、API key、模型列表和本地代理端口等结构化配置改成难以扫描的插画对象。网络方式使用紧凑分段选择，本地代理只在选中后显示端口输入，不展开协议内部字段。

连接测试当前使用“线缆信号”反馈：工作中显示信号移动，成功显示接通印记，失败显示断开点和可信原因。这些是可以重做的表现方案；新方案只需让结果与当前连接的关系保持清楚。

本机 Whisper 设置使用一个连续场景表达查看、调整或活动任务。稳定状态只保留当前模型、来源、实际运算方式、就绪状态和一个“调整方案”动作；编辑时在原位置展开并列模型卡、本地文件夹入口和运算方式，字段差异与下载计划合并为一份靠近主动作的摘要。下载开始后，编辑器离场并由真实阶段、进度和取消动作接管主体。完成和失败可以强烈演出，但最终画面必须保留真实结果、取消或恢复动作。

## 9. 任务处理与编辑

- 任务行可以是制作单、物件、轨道或其他有空间层次的形态；选中关系不限于边签或夹子。
- 事件记录要保持可扫描的时序和语义，可以根据阶段建立不同动态形态、材质和颜色。
- 结果编辑器以阅读和编辑效率为功能底线，不限制风格只出现在选中、问题、保存和导出位置。当前的暖黄边签、窄纸带和浅蓝校时尺都是可以重做的实现选择；只要长字幕的浏览、选择、输入、校验和虚拟化性能仍然成立，布局和视觉隐喻可以大幅探索。
- 跨任务“待校对”、“修改待导出”和“导出失败”必须在文案和恢复动作上明确区分；当前的暖黄纸签、冷色胶带和修理纸带不构成后续动效与场景方案的限制。
- 内部诊断字段不因“看起来专业”重新进入普通界面。

## 10. 验收

每次视觉调整至少检查：

- 静止截图是否已经摆脱普通后台或默认 Flutter 表单的视觉印象。
- 启动、关键状态跨越和退出是否具有足够明确的技术展示、情绪张力和品牌记忆点。
- 去掉颜色后，选择、状态和主次是否仍可理解。
- 场景演出的起点、中间帧、结束和减少动态效果版本是否完整，中断或超时是否不会留下黑屏、透明点击区或无法退出的窗口。
- 长名称、缺配置、失败和工作中状态是否保持可读。
- Release 窗口是否无 overflow、空白画布和错误资源，场景级效果是否在目标 Windows 设备上满足帧时间和显存预算。
