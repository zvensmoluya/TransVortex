# Flutter 视觉对象与交互反馈规范

本文档决定 TransVortex 如何通过世界对象、线条、材质和反馈节奏表现为二次元可爱风原生客户端。

它不把某组色值当作设计起点。颜色服务于对象关系、注意力和可读性；实际色值允许根据真实 Windows Release 上屏效果调整。`tokens.dart` 是当前实现快照，不是审美边界。

## 1. 视觉气质

TransVortex 是安静的个人字幕译制工作间，不是游戏界面、糖果色组件库或带角色皮肤的后台管理台。

- 工作面克制、稳定、适合长时间使用。
- 可爱感集中在物件形态、墨线、纸张细节、选择反馈和状态变化。
- 不依赖大面积插画、角色常驻、彩色卡片或装饰性动画证明风格。
- 表单可以保持表单；效率优先的编辑器可以保持工具密度。

## 2. 世界对象

| 对象 | 产品含义 | 常见位置 |
| --- | --- | --- |
| 封套 / 投递口 | 片源、当前任务 | 主窗口 |
| 字幕纸带 | 正在制作的内容、产出结果 | 主窗口、结果编辑 |
| 纸签 | 模型、语言、格式等短信息 | picker、设置窗 |
| 胶带 / 夹子 | 选中、固定、默认关系 | 连接列表、常用模型 |
| 线缆 / 信号点 | 服务连接和测试过程 | 翻译、识别设置 |
| 印章 | 保存成功、制作完成 | 主动作、完成态 |
| 修理便签 | 失败原因和恢复动作 | 主窗口、任务处理 |

这些对象可以只是局部轮廓、边缘、缺口或运动方式，不要求每次都画成完整插画。

## 3. 颜色原则

- 大面积工作面保持低彩度，为文字和物件留出注意力。
- 草莓粉继续承担品牌焦点，但不要求所有可点击元素都用粉色描边。
- 其他颜色只有在能改善层级、材质或语义时才使用；不按“每种状态必须有一种颜色”机械分配。
- 成功、失败、注意优先依靠形状和文字，颜色只做强化。
- 同一窗口上屏协调优先于跨窗口机械复用同一个色值。
- 调色必须通过真实 Release 截图判断，不以 token 数量、色相数量或设计表格完整度作为完成标准。

## 4. 反馈节奏

| 交互 | 反馈 | 建议时长 |
| --- | --- | --- |
| hover | 物件或纸签轻抬、墨线加深、局部提亮 | 90-140ms |
| press | 原位下压或轻微缩放，不改变布局尺寸 | 70-110ms |
| 选择 | 胶带边、夹子或纸签位置变化；文字保持可读 | 140-220ms |
| 异步工作 | 当前动作原位进入工作态，显示持续但克制的运动 | 持续到结束 |
| 成功 | 一次盖章、勾印或纸带就位 | 220-360ms |
| 失败 | 修理便签或断开的信号出现，直接连接恢复动作 | 160-260ms |

动画只解释状态变化。所有固定格式控件必须保持稳定尺寸，不能因 hover、loading、长文案或图标出现而推动布局。

## 5. 应用图标

- 图标沿用主窗口的胶片封套、字幕纸带和胶带对象，不使用默认 Flutter 标记、文字缩写或与产品无关的角色。
- 大尺寸母版位于 `desktop_flutter/assets/branding/app_icon.svg`；`256px` 保留胶片孔和完整纸带细节。
- 小尺寸母版位于 `desktop_flutter/assets/branding/app_icon_small.svg`；`48px`、`32px` 和 `16px` 去掉胶片孔，只保留封套折线、粉色字幕条和青色角标。
- `scripts/build_brand_assets.ps1` 生成 PNG 母版以及供窗口、任务栏、托盘和 NSIS 共用的多尺寸 ICO。生成后必须验证 `256/48/32/16` 四档都存在。

## 6. 主窗口

- 空态是打开的投递口；拖入时盖口和落点共同响应。物件下方保留新任务设置和明确的“选择片源”主动作，不能把文件选择能力藏进整块隐形点击区。
- 就绪态是收好的片源封套，任务配置仍在物件下方完成。
- 制作中不是通用 spinner：封套应表现出字幕纸带正在被处理。纸带使用九个稳定分段表达检查、读取、识别、术语、分片、翻译、对齐、质量和写出，已完成段、当前段内进度和后续段在静止截图中也应可区分；移动信号点只强化真实总体进度。
- 纸带下方使用稳定的阶段标题、分窗/分片计数和累计模型请求，短时动作只补充当前发生的批量补回、自动拆分或格式修复。不能轮播历史事件、原始日志或纯装饰文案制造“正在工作”的假象。
- 完成态让字幕纸带成为交付件，主动作自然落到结果审看；仍有质量或交付提醒时，用短句把审看责任留在完成态，不把有提醒的结果伪装成完全通过。
- 失败态使用修理贴或卡住的纸带，不能把整个窗口染成错误色。

## 7. 设置窗

设置窗保留高效表单骨架。二次元风格主要进入：

- 连接、模型和引擎的选择行。
- 字段分组标题、默认关系和选中边缘。
- 保存、测试连接、拉取模型和失败恢复的反馈。
- 菜单、picker、轻量提示和空状态。

不得为了风格把 Base URL、API key、模型列表等结构化配置改成难以扫描的插画对象。

连接测试使用“线缆信号”反馈：工作中显示信号移动，成功显示接通印记，失败显示断开点和可信原因。结果在当前连接上下文出现，不使用独立结果卡片。

## 8. 任务处理与编辑

- 任务行可以表现为扁平制作单，选中关系用边签或夹子表达。
- 事件记录使用统一的制作节点，不铺多色状态标签。
- 结果编辑器以阅读和编辑效率优先；风格集中在选中片段、问题标记、保存和导出反馈。当前问题片段使用暖黄边签和书签固定位置，交付状态使用贯穿工作区的窄纸带，不把每个字幕片段做成独立卡片。
- 跨任务“待校对”和“修改待导出”使用暖黄纸签与冷色胶带表达尚需确认，不复用失败态红色；导出失败只把交付纸带切换为修理状态，字幕列表保持原位。
- 内部诊断字段不因“看起来专业”重新进入普通界面。

## 9. 验收

每次视觉调整至少检查：

- 静止截图是否仍像普通后台或默认 Flutter 表单。
- 去掉颜色后，选择、状态和主次是否仍可理解。
- 动画关闭或截在任意一帧时，布局是否稳定。
- 长名称、缺配置、失败和工作中状态是否保持可读。
- Release 窗口是否无 overflow、空白画布和错误资源。
