## 1. 要解决的问题

当前所有次级界面（翻译设置 / 语音识别设置 / 诊断 / 结果审看 / 任务历史 / 任务详情）都走同一条路 [`_openToolWindow`](../../../desktop_flutter/lib/main.dart)，开一个独立 OS 子窗口，而几何策略在 [`current_window_controls.dart`](../../../desktop_flutter/lib/services/current_window_controls.dart) 里**七种窗口共用一套、写死**：

- 全部 `center: true` —— 每个都开在正中；
- 全部比主窗大（主窗 720×520，子窗 760–900 宽）—— 每个都盖住主窗；
- 全部 `setResizable(false)` + `setMaximizable(false)` —— 一律不可缩放；
- 尺寸雷同、无相对主窗的位置关系、无「这是什么类型的窗」的身份区别。

**症状：** 点任何东西都弹出「比主窗大、居中、盖住主窗、不能改大小」的盒子，体感等同浏览器换路由。子窗口本身没错，错在**七种内容被塞进同一个模具，缺少角色和几何纪律**。

额外的重灾区是**窗口增殖**：任务历史每行甩 4 个按钮 [`_HistoryTaskRow`](../../../desktop_flutter/lib/widgets/task_history_window.dart)，其中「详情」「审看结果」各自**再开一个独立居中窗**（[`_openDetail`](../../../desktop_flutter/lib/widgets/task_history_window.dart) / [`_openResult`](../../../desktop_flutter/lib/widgets/task_history_window.dart)）。于是「历史窗 → 又炸出详情窗 + 审看窗」，三窗互相盖、无空间关系。

## 2. 和硬规则的关系（重要：解法方向的澄清）

硬规则 §9 / §11 / §12 已经明确：任务详情、事件、诊断、修复、高级设置**应优先用原生子窗口 / 系统 dialog / 固定 inspector / 工具窗**；主窗口**不得**用铺满窗口的 Overlay / 半透明遮罩当默认弹窗；把这些做成**主窗口内嵌 modal 属于停止条件**。

**结论：** 修复方向**不是**把次级界面融回主窗口做浮层/抽屉（那会撞停止线，重演 archive 里 `2026-05-web-workbench-failure` 的 Web 工作台化）。修复方向是——

> **保留原生子窗口，给它们明确的「角色」和「几何纪律」，并干掉窗口增殖。**

用户对「Web 路由感」的不满和硬规则想要的是同一件事；分歧只在手段。本提案取规则认可的手段（更好的原生窗口），不取「融入主窗」。

规格 §13 已把「任务历史 / 任务详情 / 事件 / 完整结果编辑器的窗口与世界归位」列为**留待后续设计**——本提案是在填这个主动留的空，不是推翻现有规格。曾与规格 §5/§6 唯一可能冲突的「翻译+识别合并成一个窗」，已决定**不合并**（见 §8），无冲突。

## 3. 判据：用「同时性」决定窗口角色

对每个次级界面问一句：

> **用户会想把它和主窗（或另一个任务）并排摆着、同时用吗？**

- **会** → 它是**工作台**：可缩放、可最大化、记忆几何；是否多开按数据冲突和编辑语义单独定。
- **不会**（顺序发生：配好→跑、配一次就走） → 它是**工具窗**：单一职责、定位偏移不居中盖、用完即走、同类单例。

这条判据只决定**角色与几何**，不决定「进不进主窗」——次级界面一律留在子窗口（服从硬规则）。

## 4. 窗口角色分类

| 角色 | 定义 | 几何 | 例子 |
| --- | --- | --- | --- |
| **主窗** | 单会话、单主体工作面（规格 §4，不变） | 固定 720×520、不缩放、无路由、无分栏 | 主窗口 |
| **工具窗** | 顺序性的单一职责界面，做完即走 | 尺寸按内容、**相对主窗偏移/层叠而非居中盖**、同类单例并 focus 已存在实例、可轻度缩放 | 翻译设置、语音识别设置、诊断 |
| **工作台** | 有真实「同时看两个」需求的重度活动 | **默认大 + 可缩放 + 可最大化 + 记忆几何**；一期同类单例，第二实例留二期 | **任务处理窗**（任务片列 + 审看/编辑 + 恢复动作） |

关键纪律（这四条直接消灭「Web 路由感」）：

1. **不再一律居中盖主窗**：工具窗相对主窗偏移或层叠，工作台记忆上次位置；主窗始终可见一部分，窗口才像窗口而不像路由。
2. **可缩放性按角色给**：工作台必须可缩放/最大化（现在 `setResizable(false)` 对结果编辑器是明确 bug）；工具窗可轻度缩放。
3. **同类单例 + focus 已存在**：已有 [`_toolWindows`](../../../desktop_flutter/lib/main.dart) map 做了一半，补齐所有类型。
4. **窗口不得为「导航」而开窗**：一个窗口内部要看同类里的另一条，用**窗内 master-detail 选中**，不 spawn 新窗（见 §6）。

## 5. 现有表面 → 目标角色与几何

| 现在的窗口 | 会想并排同时用？ | 目标角色 | 几何变化 |
| --- | --- | --- | --- |
| 翻译模型设置 | 否（配一次，规格 §2） | 工具窗 | 偏移不居中；单例；右详情区已允许局部滚动 |
| 语音识别设置 | 否 | 工具窗 | 同上 |
| 诊断 | 否 | 工具窗（主窗可有状态入口，但展开仍进入诊断工具窗 / 系统 dialog） | 偏移；单例；只读 |
| 任务历史 | 否（但与编辑/恢复同域） | **并入任务处理窗的任务片列** | 不再独立成窗 |
| 任务详情 | 否 | **并入任务处理窗**（选中任务的概览/日志/恢复动作） | 不再独立成窗 |
| 结果审看/编辑 | **是** | **任务处理窗的编辑工作台** | **可缩放/最大化/记忆几何；一期同类单例** |

净结果：真实顶层窗口类型从 7 收敛到 **5**（主窗 + 3 工具窗〔翻译 / 识别 / 诊断〕 + 1 任务处理窗）——**任务处理窗吞掉了任务历史 + 任务详情 + 结果审看三种旧窗**；几何策略从「一刀切」变「按角色」。

## 6. 任务处理窗：任务片列、详情、编辑合一

历史、详情、编辑和恢复是**同一个域**：用户不是在管理记录，而是在找到一个任务后，决定它接下来该被打开、修、续跑、重导出，还是认真审看。完成任务能进入结果编辑；失败任务要看原因、继续或重试；运行中任务只读观察。把这些合成**一个可缩放的「任务处理窗」**，而不是三种窗互相拉起；这一并把旧的**任务历史 + 任务详情 + 结果审看三种窗收敛成一个**，也彻底消灭 §1 的窗口增殖。

判据仍然成立：处理窗因为**编辑**这个重度活动而是工作台（可缩放窗）；历史不是因为需要同时性，而是作为任务处理窗里的**任务片列**（master-list）挂在里面。资源未定前先按扁平任务片设计，不绑定「罐 / 盒 / 胶片卷」这类具体物件；以后若补世界物件，可把任务片升级成胶片或封套外观。**它读起来应是一处任务处理工作面，不是"历史管理页 + 详情页"。**

**布局 = 任务片列 + 工作台，按你在干嘛调权重（不是常驻五五分栏）：**

```
浏览（从 ≡「任务历史」进）：           编辑（点某片的「编辑」）：
┌────────┬────────────────┐          ┌─┬──────────────────────┐
│ ▣ 片   │ 选中任务预览     │          │▣│  源 / 波形            │
│ ▣ 片   │ + 轻动作         │   ──►    │▣│  ─────────────────   │
│ ▣ 片   │  打开/续跑/修复   │          │▣│  分段1  译文…         │
│ ▣ 片   │  〔编辑〕        │          │▣│  分段2  译文…         │
└────────┴────────────────┘          └─┴──────────────────────┘
  任务片列    轻预览                    窄任务列 工作台占满
```

- **任务片列**：最近任务列表，每个任务先是一条**扁平任务片**，用状态形状、短摘要和主动作区分完成 / 失败 / 运行中 / 已取消。完成任务给「编辑 / 打开字幕 / 打开文件夹 / 重新导出」；失败任务给「看原因 / 继续 / 重试 / 打开任务目录」；运行中任务给只读观察和刷新。**不是"文件名 + 状态 badge + 一排按钮"的表格行**。这是硬规则 §11 的线——同是"左列表 + 右面板"，做成任务片列是原生工作面的对象列，做成表格就是后台管理台。
- **两种权重**：浏览时任务片列为主 + 选中任务的轻预览；点某片「编辑」→ 工作台占满、任务片列收成一条**可再展开的窄任务列**。所以它是**能藏的对象列，不是常驻导航栏**。
- **工作台内部**：源 / 波形 + 分段列表 + 逐段改译文；概览 / 事件日志 / 恢复建议作**辅助信息**（侧栏或可展开），含对 `can_resume` 任务的继续动作。失败任务不被挤给诊断窗；诊断只负责环境和配置问题的定位。**不做顶部 tab**（守住"窗内不做区段切换"）。
- 「点任务片 → 右侧换内容」是 **master-detail 选中，不是导航**，合法且原生（Finder 式对象选择）。
- **几何**：默认大（约 1040×720 起）、可缩放、可最大化、记忆几何；一期按同类单例处理，已有实例则 focus，并定位到目标任务。并排比两个任务的第二实例留二期。

**单例定位协议（实现必须落下去）：** 任务处理窗按**窗口类型单例**，不是按 `task_id` 多开。主窗完成态、任务片轻动作、诊断里的可恢复任务入口都只能表达「打开任务处理窗并定位到某任务 / 某模式」。如果任务处理窗已存在，应 focus 已有窗口并发送定位请求（选中目标任务，必要时切到编辑态或恢复信息），而不是按 `task_id` 再 spawn 一个新窗。当前 [`_openToolWindow`](../../../desktop_flutter/lib/main.dart) 的 `_toolWindows` key 是 `type:taskId` 粒度；合并后要为任务处理窗改成「类型 key + 窗内定位命令」，否则会把窗口增殖换一种形式带回来。

## 7. 处理窗入口与主窗完成态

**一个窗，两个入口：**

- 主窗**完成态**点「审看/编辑」→ 进任务处理窗，**定位到刚做完的任务片**（任务片列收起、直接进工作台）；
- 标题栏 `≡` 的「任务历史」→ 进**同一个**任务处理窗，停在**任务片列**（浏览态）。

**主窗完成态只保留"结果一瞥"**：打开字幕 / 打开文件夹 / 重新导出（规格 §8 已有）；**认真编辑才升到处理窗**——即「用户在乎时点进去，是想好好处理一番」。

**glance-and-go 不必进工作台**：只想扫一眼、打开文件夹、继续失败任务或重试，就直接点任务片上的**轻动作**，不展开工作台。这样合成一个大窗后，"轻量查看 / 轻量修复"也不显得重。

## 8. 已定：翻译与识别各一个工具窗（不合并）

**决定（2026-07-06）：不合并。** 翻译模型设置与语音识别设置各自保留一个工具窗。

先分清两条常被混在一起的轴：

- **轴一 · 配置层（决定"家在哪"，规格 §2，不变）**：
  - **运行时/任务配置**（这一单选哪个模型/引擎、双语、格式）→ 家在**主窗 job 描述的可点词**。
  - **后备/准备配置**（有哪些 provider、key、base_url、引擎参数、默认+备用模型）→ 家在 **≡ 菜单的工具窗**。
- **轴二 · 后备层内部（翻译域 vs 识别域）**：**各一个工具窗**；不合并，也不把任一域塞进主窗。「asr 和模型配置放哪」这个问题整个落在后备层，与轴一无关。

为什么不合并：两者结构本就不同（翻译=服务列表 master-detail；识别=三选一 segmented + 参数），合并只有两条路——加**窗内区段切换器**（犯「窗内不做导航」忌），或把两个异形表面**长滚动堆叠**（别扭）。且规格 §2 已把准备配置定为**低频（配一次）**，高频的选用早在主窗可点词里，"高频→值得合并"不成立。

**内部构图沿用规格 §5/§6，本提案不重画**；只改这两个窗的**几何/身份**（相对主窗偏移不居中盖、同类单例、轻度可缩放）：

- **翻译设置窗** = 两栏 master-detail + 顶部常驻默认模型条。左=服务扁平列（整行高亮选中，非卡片；服务多则**窄栏局部滚**）；右=选中服务详情表单（base_url / key 不回显 / 拉模型列表 / 测试 / 设默认；内容长则**局部滚**）。点左选右=选中，非导航。
- **识别设置窗** = 顶部三选一 segmented（本机 / FunASR / 云端）+ 选中引擎参数，基本一屏**不靠滚**。

**滚动纪律**：只允许"某一栏溢出时的局部滚动"（规格 §12 已认可右详情局部滚动）；**禁止整窗一条大滚动**当主骨架（硬规则 §9）。这俩窗是**有世界物件的原生配置窗**（规格 §5 Z4 / §6 Z3 的装置位），不是 web 表单；表单密度只准待在这里，不许漏回主窗。

其余各项（几何纪律、任务片列 master-detail、任务处理窗 / 编辑工作台、砍窗口增殖）都落在规格 §13 已留的开放区内，属于**填空**而非改规格，评审通过即可回填。

## 9. 几何策略重写（落点）

[`current_window_controls.dart`](../../../desktop_flutter/lib/services/current_window_controls.dart) 的 `configureCurrentWindow`：

- switch 从「按类型给尺寸、全部 center + 不可缩放」改为「**按角色给几何**」：主窗（固定）、工具窗（偏移定位、轻度可缩放、单例）、工作台（大、可缩放/最大化、记忆几何）。
- 去掉工作台的 `setResizable(false)` / `setMaximizable(false)`。
- 居中改为相对主窗偏移/层叠或读取上次几何。实现上不能只在子窗口里猜位置：主窗口创建子窗口时应传入主窗 bounds / 建议 frame，或子窗口通过 `WindowStateBridge` 请求主窗 bounds；只有拿不到主窗几何时才允许退回安全默认位置，不能悄悄退回全部 `center: true`。
- 几何记忆要按**窗口角色 + 窗口类型**分 key：工具窗只记同类最后位置 / 尺寸，任务处理窗记工作台几何；不要按 `task_id` 记一堆历史任务窗口位置。
- 恢复几何前必须做**屏幕可见性校验**：多显示器变更、DPI 缩放变化、窗口落到不可见屏幕外时，回收到当前主屏可见区域内。至少保证标题栏和主要操作区可触达。
- 提供一个「恢复默认窗口位置 / 尺寸」的内部能力（可以先只在调试命令或后续菜单里暴露），防止记忆几何把用户锁在坏状态里。
- 工具窗偏移建议走稳定层叠：以主窗左上或右上为锚点，按同一会话内已开工具窗数量轻微错开；不能因为子窗比主窗宽就重新退回正中盖住主窗。

## 10. 迁移成本（如实标注）

- 此前 release smoke 是**按窗口类型逐个驱动**的（[`main.dart`](../../../desktop_flutter/lib/main.dart) 的 `_runStartupSmoke` 带 `window_type`；`smoke_flutter_release_matrix.ps1` 原有 `-WindowType translationSettings/asrSettings/diagnostics/resultReview/taskHistory/taskDetail` 六个非主窗口 case）。当前已收敛为正式工具窗 `translationSettings` / `asrSettings` / `diagnostics`、任务处理窗 `taskProcessing` 以及 `taskProcessing` browse / edit / failure / resume / cancel 覆盖；旧 `resultReview` / `taskHistory` / `taskDetail` 独立窗口类型和 release smoke case 已移除。
- **任务历史 / 任务详情 / 结果审看三种旧窗合并成任务处理窗**、几何按角色重写后，这些 smoke 入口已经改写：`taskHistory` / `taskDetail` / `resultReview` 三个 `-WindowType` case 收敛为任务处理窗的浏览态 / 编辑态 / 失败线索停留态 / 失败恢复态 / 运行中取消态，工作台改为可缩放；原 `taskDetail` smoke 覆盖的 `runtime.submitResume` 继续任务能力已迁到任务片选中失败任务后的轻动作里。剩余验证重点不再是旧窗口兼容，而是继续补完整真实可见任务链路和后续恢复矩阵。

建议实施拆成四步，不要一次全吞：

1. **先改窗口角色与几何**：保留现有六个子窗口内容，只把主窗 / 工具窗 / 工作台的尺寸、可缩放性、偏移定位、同类 focus 行为和基础 smoke 调整好。这样先消掉最刺眼的「居中盖住且不可缩放」。
2. **再引入任务处理窗壳**：新增一个任务处理窗入口，先接 `tasks.list`、选中任务预览、完成任务编辑入口和失败任务继续动作；这一步允许旧 `taskHistory` / `taskDetail` / `resultReview` 入口短期并存，但菜单和完成态优先走新窗。
3. **再把结果编辑器嵌入处理窗**：复用旧结果审看窗已验证的 `result.open` / `result.segments.save` / `result.reexport` 能力，但作为任务处理窗右侧工作台显示，不再从任务片列 spawn 新结果窗；旧 `resultReview` 窗口类型短期只作为 release smoke / 回退路径保留。
